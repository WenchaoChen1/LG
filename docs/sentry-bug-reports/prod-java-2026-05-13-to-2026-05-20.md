### 1. LG-PROD-JAVA-30 + 37 — 公司财务数据链整体崩溃（27594 events 合计）

两个 issue 来自**两家不同公司**，但都是同样的"数据缺失链崩溃"模式（与 UAT-1N+1E 同源）：

| Issue | 错误 | 影响公司 | Events |
|-------|------|---------|--------|
| **LG-PROD-JAVA-30** | `NormalizationBuildException: closeMonthData is null` | `deaa9ad4-4a0d-4627-9ac1-402f48ca9d8c` | 13996 |
| **LG-PROD-JAVA-37** | `ForecastBuildException: Latest official financial data is empty` | `f62d029d-5227-4c7d-a18f-d20680ee7332` | 13598 |

- **代码位置**:
  - `FinancialForecastDataServiceImpl.java:672` `buildForecastDataForCompanyById`
  - `FinancialNormalizedServiceImpl.java:145` `buildFinancialNormalizationForCompanyProcess`
- **Sentry 链接**:
  - https://lookingglass-3t.sentry.io/issues/LG-PROD-JAVA-30
  - https://lookingglass-3t.sentry.io/issues/LG-PROD-JAVA-37

**根因**：这两家公司可能没有 actuals 数据 / 没接 QBO / 数据状态异常。代码遇到空数据直接抛 exception → SQS 消费者反复重试 → 累积近 28000 events。

**修改方案**（与 UAT 报告一致）：

```java
// FinancialForecastDataServiceImpl.buildForecastDataForCompanyById
FiDataDto latestCurrentData = getLatestOfficialData(...);
if (latestCurrentData == null || latestCurrentData.isNull()) {
  log.warn("[forecast] company has no actuals, skip: companyId={}", companyId);
  return;  // 不抛 ForecastBuildException
}

// FinancialNormalizedServiceImpl.buildFinancialNormalizationForCompanyProcess
if (closeMonthData == null) {
  log.warn("[normalize] no close month, skip: companyId={}", companyId);
  return;
}
```

**数据层**：定位 `deaa9ad4-...` 和 `f62d029d-...` 这两家公司，确认是否需要：
- 标记 active=false 跳过处理
- 补 actuals 数据
- 添加到默认跳过列表

## 🟡 P1 - 本周修

### 2. LG-PROD-JAVA-3M — **KpaReview.getStage() NPE（已在生产复现）**

> ⚠️ 这是用户之前手动贴过的 NPE，已在生产稳定复现。

- **原标题**: `NullPointerException: Cannot invoke "com.gstdev.cioaas.web.di.domain.Stage.getId()" because the return value of "com.gstdev.cioaas.web.di.domain.KpaReview.getStage()" is null`
- **Sentry 链接**: https://lookingglass-3t.sentry.io/issues/LG-PROD-JAVA-3M
- **代码位置**: `KpaBusinessServiceImpl.java:504` `kpaReviewList`
- **请求路径**: `GET /web/kpaBusiness/kpaReviewList`

**根因**（前置完整分析见之前的对话回顾）：

数据库里某些 `kpa_review.stage_id` 为 NULL（脏数据 / 历史遗留），第 504 行直接调 `kpaReview.getStage().getId()` 抛 NPE → 整页 KPA Review 列表 500。

**真正的 NULL 写入源头**（创建路径的隐藏 bug）：
- `StageServiceImpl.saveCompanyStage:133-136` 允许 `stageId` 为空时不设 stage
- `CompanyServiceImpl.getStageByCompanyId:2461` 透传 null（仅防御空列表，未检查 stage 本身）
- `KpaBusinessServiceImpl:402` 接到 null + `:444` 透传 setStage(null) → 入库

**修改方案**（三层防御）：

```java
// (1) KpaBusinessServiceImpl.kpaReviewList:504 防御读
for (KpaReview kpaReview : kpaReviewList) {
  Stage stage = kpaReview.getStage();
  stageIdMap.put(kpaReview.getId(), stage != null ? stage.getId() : null);
}

// (2) StageServiceImpl.saveCompanyStage:133 拒绝空 stageId
if (ObjectUtil.isEmpty(companyStateDto.getStageId())) {
  throw new BadRequestException("stageId is required");
}

// (3) CompanyServiceImpl.getStageByCompanyId:2467 真正校验 null
Stage stage = rCompanyStages.get(0).getStage();
if (stage == null) {
  throw new BadRequestException("company has no stage configured");
}
return stage;
```

// QuickbooksQueryService.getQuickbooksMaxPullTime
public Instant getQuickbooksMaxPullTime(String companyId) {

  if (StringUtils.isBlank(maxPullTimeStr)) {
    return null;  // 让上层 getLastSyncTime 容忍 null
  }
  return Instant.parse(maxPullTimeStr);
}

// FiDataCalculateServiceImpl.getLastSyncTime
public Instant getLastSyncTime(...) {
  Instant lastSync = quickbooksQueryService.getQuickbooksMaxPullTime(...);
  return lastSync;  // null safe
}

### 5. LG-PROD-JAVA-31 — GitHub API 404（9504 events）

- **原标题**: `GitHub API returned status=404 for url=https://api.github.com/repos/tango-admin-portal/stats/code_frequency`
- **Sentry 链接**: https://lookingglass-3t.sentry.io/issues/LG-PROD-JAVA-31
- **代码位置**: `GithubApiClient.get`

**根因**：URL `repos/tango-admin-portal/...` **缺少 owner 段**（应是 `repos/<org>/tango-admin-portal/...`）。`github.repo.owner` 配置可能为空字符串。

**修改方案**：

```java
public JSONObject get(String path) {
  if (StringUtils.isBlank(owner) || StringUtils.isBlank(repo)) {
    log.warn("[github] owner/repo not configured, skip: path={}", path);
    return null;
  }
  // ... 404 时返回 null 不抛 RuntimeException
}
```

并核对配置：`github.repo.owner` 是否被某些公司的配置覆盖成空。
