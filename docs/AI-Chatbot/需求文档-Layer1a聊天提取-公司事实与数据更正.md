# 需求文档：Company Memory File Layer 1a 后端 — 聊天提取：公司事实与数据更正

**来源任务**：Company Memory File Layer 1a Backend - Chat Extraction: Company Facts & Data Corrections
**Asana 链接**：https://app.asana.com/1/1170332106480422/project/1202050347057533/task/1214953638826103
**适用模块**：AI Chatbot Layer 1a 后端 — 公司端聊天的实时增量提取
**类型**：后端与数据架构需求（**无用户可见 UI**）

---

## 一、背景与范围

本需求覆盖**公司端聊天对话**中第一类内容的**实时增量提取**到 Layer 1a 记忆文件：

- **公司事实（Company Facts）**：在 LG 结构化数据中没有对应字段的、创始人在对话中以自然语言分享的事实；
- **数据更正（Data Corrections）**：用户对 LG 已存数据（特别是 Normalization Table 中的财务数据）所做的更正或澄清。

提取在对话发生时**实时进行**——系统在每次消息交换发生时评估其中是否含有合格信息，并在上下文完整时**立即提取**。提取**异步运行**，**不阻塞**或延迟 AI 回复的交付。仅提取**新的或有修正性**的信息；已经存于记忆文件中的信息不会重复提取，**除非**它与既有条目相矛盾或对其进行实质性更新。

---

## 二、功能描述

### 2.1 提取触发

- 提取为**实时增量**：系统在每次用户消息和 AI 回复交换发生时即评估；
- 提取处理**异步运行**，不阻塞或延迟 AI 回复的交付；
- 每次仅评估**最近一次交换**中是否有合格内容；不再次处理整段会话历史。

### 2.2 公司事实（Company Facts）— 三个子维度

为使分类清晰且与其他提取需求不重叠，公司事实由以下三个**子维度**共同定义：

#### 2.2.1 子维度 A：Business Milestones & Recent Events（业务里程碑与近期事件）
- 公司近期经历的**重要事件或成就**，例如：
  - 拿下首位客户或重要客户；
  - 进入新市场；
  - 达到某收入或增长门槛；
  - 推出关键计划（initiative）；
  - 经历重大运营变更；
- 这是**有时点、具体可记入**的事实，区别于 Strategic Context 需求中持续性的战略挑战与模式；
- 关键区分：**里程碑与近期事件**是具体、可标注日期的发生事项，**不是**持久的模式。

#### 2.2.2 子维度 B：Funding & Capital Activity（融资与资本活动）
- 公司**融资历史与当前资本状况**，包括：
  - 已完成的融资轮次与金额；
  - 当前投资人关系；
  - 公司当前是否在主动融资；
  - 创始人在对话中提到的任何其他资本活动；
- **明确排除**：
  - 持续性的收入或财务表现数据——这部分由上传的财务数据与 normalization table 捕获；
  - **现金跑道（runway）计算**——它由 LG 已有财务数据派生。

#### 2.2.3 子维度 C：Industry & Regulatory Context（行业与监管背景）
- 公司所处的**外部环境**，包括：
  - 行业特定的合规要求；
  - 监管批准或约束；
  - 公司持有或正在追求的认证；
  - 重大影响公司运营或 GTM 的政策或市场变化；
- 与 Competitive Landscape 提取需求的关键区分：本子维度关注**结构性外部环境**，**不是**竞争动态（竞争对手与替代品在 Competitive Landscape 中处理）。

### 2.3 数据更正（Data Corrections）

- 当创始人指出 LG 中某个值（**Normalization Table** 中的值）**不正确或已过时**时，捕获该更正；
- 示例：
  - "that revenue figure for March is wrong, it should be $1.1M"；
  - "our ARR is actually higher now because we closed a deal last week that hasn't synced yet"；
- 这些更正**作为上下文存储**在 Layer 1a 记忆文件中，便于 AI 在回答相关数据问题时引用；
- **关键约束**：
  - 在记忆文件中存储更正**不触发**对财务数据、normalization table、预测或任何其他 LG 数据结构的下游更新；
  - 将更正向下游传播的能力**明确属于 MVP 之后**的范围。

### 2.4 冲突与更新处理

- 若新提取的事实或更正**矛盾或实质性更新**了一条已有记忆条目，**更新**已有条目以反映最新信息；
- **防止重复**：不重复提取已存于记忆文件中的信息。

### 2.5 性能与错误处理

- 提取**异步运行**，不阻塞或延迟 AI 回复；
- 失败的提取尝试**记录日志**用于排查，**不向终端用户暴露**任何错误；
- 即使单次提取失败，Chatbot **继续正常运作**。

## 三、验收标准

### 3.1 提取触发
- 提取为实时增量；系统在每次用户消息与 AI 回复交换发生时即评估；
- 提取处理异步运行，不阻塞或延迟 AI 回复；
- 仅评估**最近一次交换**中的新增合格内容，不重处理完整会话历史。

### 3.2 公司事实 — Business Milestones & Recent Events
- 正确识别并提取对话中浮现的重要业务里程碑与近期事件，包括拿下首/重要客户、进入新市场、达到收入或增长门槛、推出关键计划、经历重大运营变更；
- 已提取的里程碑与事件作为 Layer 1a 记忆条目存储，附 source type（chat extraction）与时间戳；
- 不构成重大业务进展的**日常运营活动与轻量日常事件**被排除；
- 持续性的战略模式与挑战**不在**本子维度内，由 Strategic Challenges 提取需求处理。

### 3.3 公司事实 — Funding & Capital Activity
- 正确识别并提取对话中提到的融资与资本活动，包括已完成的融资轮次与金额、当前投资人关系，以及公司当前是否处于融资过程中；
- 融资与资本条目作为 Layer 1a 记忆条目存储，附 source type（chat extraction）与时间戳；
- **持续性的收入或财务表现数据**明确排除——通过财务数据管线与 normalization table 捕获；
- **由财务数据派生的 runway 计算**排除——仅直接表述的资本上下文符合资格。

### 3.4 公司事实 — Industry & Regulatory Context
- 正确识别并提取对话中浮现的行业与监管背景，包括行业特定合规要求、监管批准或约束、公司持有或正在追求的认证、对运营或 GTM 有实质影响的政策或市场变化；
- 行业与监管条目作为 Layer 1a 记忆条目存储，附 source type（chat extraction）与时间戳；
- **竞争对手特定上下文**明确排除——由 Competitive Landscape 提取需求处理；
- 与本公司运营无具体相关性的**通用行业观察**被排除。

### 3.5 公司事实 — 通用排除
- 通用信息性提问、事务性交换、不构成事实性公司信息的观点性陈述，在三个子维度中均排除；
- LG 结构化数据（Company Settings、财务数据或已有记忆条目）中已**准确捕获**的信息，**不再**作为新记忆条目重新提取。

### 3.6 数据更正提取
- 正确识别用户指出 LG **Normalization Table** 中某个值不正确或过时的情形；
- 更正作为 Layer 1a 记忆条目存储，附 source type（chat extraction）、时间戳、以及**足以识别被更正数据点与更正值**的上下文；
- 在记忆文件中存储更正**不触发**对财务数据、normalization table、预测或任何其他 LG 数据结构的更新——明确属于 MVP 之后范围；
- AI 在后续回答涉及该数据点的问题时，**可引用**已存的更正（例如被问到 March revenue 时，AI 可同时呈现已存的 LG 值与该更正）。

### 3.7 冲突与更新处理
- 若新提取产生与已有条目相矛盾或对其实质性更新的事实/更正，**更新**已有条目以反映最新信息；
- **避免重复提取**已存于记忆文件中的信息。

### 3.8 性能与错误处理
- 失败的提取尝试**记录日志**用于排查，不向终端用户暴露任何错误；
- 即使单次提取失败，Chatbot **继续正常运作**。

## 四、范围边界与跨需求约束

| 内容 | 归属 |
|---|---|
| 业务里程碑、近期事件 | **本需求**（公司事实 — 子维度 A） |
| 融资与资本活动 | **本需求**（公司事实 — 子维度 B） |
| 行业与监管背景 | **本需求**（公司事实 — 子维度 C） |
| 对 Normalization Table 数据的更正 | **本需求**（数据更正） |
| 持续性战略挑战与模式 | Strategic Challenges 提取需求 |
| 竞争对手与替代品 | Competitive Landscape 提取需求 |
| 持续性收入 / 财务表现数据 | 财务数据管线 + Normalization Table |
| 从财务数据派生的 runway 计算 | 由 LG 既有派生 |
| 更正向下游 LG 数据结构的传播 | **MVP 之后**（明确不在本需求内） |
