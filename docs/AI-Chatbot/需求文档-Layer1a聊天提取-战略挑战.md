# 需求文档：Company Memory File Layer 1a 后端 — 聊天信息提取：战略挑战

**来源任务**：[Asana LG-1427](https://app.asana.com/1/1170332106480422/project/1202050347057533/task/1215298512189420)
**UI 需求**：无（纯后端 / 数据架构 Story）

---

## 一、背景与业务目标

本需求覆盖从公司侧（Company-side）聊天对话中，**实时、增量式**地提取**战略挑战（Strategic Challenges）**。

战略挑战是**最具行动价值的记忆上下文类别之一**——了解一家公司**持续在与什么作斗争**使 AI 能够：
- 主动浮现相关指导；
- 在挑战恶化或改善时予以标记；
- 将战略建议放在**真实的、正在进行的障碍**这一上下文中提出，而非泛泛假设。

### 合格挑战的核心特征：**Staying Power（持续性）**

合格战略挑战的定义性特征是**持续性**——必须是**跨多次会话相关、反映持续性模式（persistent pattern）而非一次性事件**的挑战。

- **属于持续性挑战**："销售效率问题已持续 6 个月" → 合格。
- **属于一次性事件**："上周某笔交易告吹" → 不合格。

系统必须**一致地应用此区分**：**只存储模式，不存储单次实例**。

### 合格战略挑战的示例
- 持续的**销售效率问题**——客户获取成本（CAC）与新增 ARR 不成比例；
- 在目标 ICP 上**未能获得增长势头**的上市动作（go-to-market motion）；
- 进入**新细分市场**时的产品市场契合（PMF）挑战；
- 与**特定使用场景或客户类型**绑定的客户留存问题；
- 在**关键职能**上的团队建设挑战；
- 在销售流程中**反复出现的竞争性替换问题**。

每种情形下，系统**存储该挑战的本质与上下文**，而**非引发它浮现的具体事件**。

### 挑战解决（Resolution）的识别

同样重要的是**对挑战解决的识别**：
- 当创始人表明先前挑战已被解决或不再令人担忧时，**已有记忆条目必须更新**以反映此变化；
- AI **不得继续引用已解决的挑战**——否则会损害用户信任、使回复显得过时。

### 提取节奏
- 提取为**实时、增量式**：在每次消息交互发生时评估；
- **异步执行**，不阻塞 AI 回复的下发。

## 二、功能需求

### 1. 提取触发机制（Extraction Trigger）
- 提取为**实时、增量式**：在每次消息交互时评估。
- **异步处理**，不阻塞 AI 回复的下发。

### 2. 战略挑战提取（Strategic Challenge Extraction）

- 系统正确识别并提取在对话中浮现的战略挑战，**定义为**：**Portfolio Manager 会希望在下次会议中记住并询问的持续性模式**。

- 提取的挑战以 **Layer 1a 记忆条目**形式存储，包含：
  - **Source Type**：chat extraction
  - **Timestamp**：时间戳
  - **足以描述挑战性质的上下文**

- **合格提取的挑战类型**包括：
  - 持续的**销售效率或 CAC 问题**；
  - 在特定 ICP 上**上市动作失败**；
  - 进入新细分市场时的**产品市场契合（PMF）挑战**；
  - 持续的**客户留存或流失问题**；
  - 关键职能上的**团队建设挑战**；
  - 反复出现的**竞争性替换问题**。

- **明确排除**——在 3 至 6 个月后将不再相关的**短暂细节**：
  - 一次性事件；
  - 具体客户姓名 / 名称；
  - 具体成交结果；
  - 孤立的事件个例。

- 系统**只存储模式及其上下文，不存储引发它浮现的具体事件**。

### 3. 挑战持续性阈值（Challenge Persistence Threshold）

- **单条消息中对困难的一次性提及**，**不足以**创建战略挑战记忆条目，**除非上下文明确表明这是一个持续性问题**。
  - 例：创始人说"我们已经为此挣扎了好几个月"——满足持续性表征。

- 系统应在将某事归类为具有持续性（staying-power）的战略挑战、而非一次过的随口评论之前，**要求足够的上下文信号**。

### 4. 挑战解决（Challenge Resolution）

- 当创始人表明先前的战略挑战**已被解决或不再令人担忧**时，**更新已有记忆条目**以反映当前的"已解决"状态。

- **已解决的挑战不删除**——而是**标记为已解决并附加时间戳**，使 AI 保留"该挑战曾存在并已被处理"的历史上下文。

- AI **不再**在后续回复中将已解决的挑战作为活跃关注点引用。

### 5. 冲突与更新处理（Conflict and Update Handling）
- 当新信息更新或取代了先前的战略上下文条目时，**更新原条目**以反映当前理解。
- **任何战略上下文的最新版本始终作为权威版本。**

### 6. 性能与错误处理（Performance and Error Handling）
- 提取失败**写入日志**，不向用户暴露任何错误。
- 即使某次提取事件失败，**Chatbot 仍正常工作**。
