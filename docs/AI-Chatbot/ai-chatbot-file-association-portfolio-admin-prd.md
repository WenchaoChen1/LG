## 一、背景

与"公司侧上传"（公司上下文天然确定）不同，Portfolio Admin 上传的文件在写入某公司的 **Layer 1b 记忆文件** 之前，必须先完成"公司归属"这一步。

本 Story 只覆盖**用户交互层**：文件上传完成后弹出的"公司归属确认"提示，允许 Portfolio Admin 在文件被写入公司记忆前，确认或修正它所归属的公司。

（后端处理逻辑由配套的 Backend Story 负责，本 Story 不覆盖；文件上传 UI 由配套的 Upload UI Story 负责，本 Story 不覆盖。）

---

## 二、业务逻辑

### 触发时机

文件上传并完成 RAG 索引后（属于配套 Upload UI Story 的范围），本流程启动。

### 系统行为

1. AI 基于**当前会话上下文**推断文件可能归属的公司。
   - 示例：如果 Portfolio Admin 在当前会话中一直在讨论"公司 A"，则 AI 推断归属公司为"公司 A"。
2. 系统弹出**公司归属确认条**（inline，不是弹窗），展示推断结果，让 Portfolio Admin 确认。
3. 如果 AI **无法自信地做出判断**，归属栏留空，Portfolio Admin 需手动从有权访问的公司列表中选择。

### 三种结果分支

| 用户操作 | 结果 |
|----------|------|
| 确认 AI 推断的公司 | 文件被处理并写入**该公司**的 Layer 1b 记忆文件 |
| 选择另一个公司（覆盖 AI 推断） | 文件被处理并写入**用户选择公司**的 Layer 1b 记忆文件 |
| 不选任何公司（留空 / 移除已选公司 / 忽略提示） | 文件**不写入任何**公司的 Layer 1b 记忆文件，仅作为**当前会话**的临时文件存在 |

### 批次归属规则（重要）

- **一批上传只归属一家公司**：同一次 composer 批次上传的所有文件必须共享同一个公司归属，不允许拆分到多家公司。
- 如果当前已选定公司时又添加了新文件，新文件自动**加入同一归属**，公司选择不重置。
- **只有在所有文件都被清空、开始新一次上传时**，才会启动新的、独立的公司归属流程。
- 同一 session 中在不同时间点发起的多次上传，各自独立触发自己的归属确认流程。

### 数据边界（重要）

- Layer 1b 上传的文件，**在任何情况下都不会**流入 GS 知识库（Layer 2）。

## 三、功能要求

### 3.1 归属确认条（Association Bar）

- 位置：**composer 上方 inline 显示**，不打断聊天。
- 明确显示：当前选中/推断的公司 + 文件将被存储的位置提示。
- **不阻断聊天**：Portfolio Admin 在归属未确认时仍可继续使用聊天功能。

### 3.2 公司选择器（Company Selector）的三种视觉状态

| 状态 | 视觉表现 |
|------|----------|
| **空（Empty）** | 虚线占位符 "Select company"，带下拉指示 |
| **AI 推断（AI-inferred）** | 已填充的 chip：公司图标 + 公司名 + × 移除按钮；公司名过长时省略号截断，hover 显示全名 |
| **用户选择（User-selected）** | 视觉上与 AI 推断状态**完全一致** —— Admin 无需区分是谁选的 |

### 3.3 公司下拉列表（Dropdown）行为

**打开方式**：点击公司槽位或已选 chip 即可打开。

**列表内容**：只展示 Portfolio Admin 有权访问的公司；每一项显示公司名。

**搜索**：顶部搜索框，输入内容实时过滤列表。

**选中态**：当前已选公司在列表中以**灰化 / 高亮**显示；再次点击该项即取消选择，归属栏回到"空 / 仅本会话"状态。

**空结果**：搜索无匹配时，显示空状态提示（例如 "No results found"）。

**滚动**：列表超过最大高度时可滚动。

**关闭条件**：
- 选中某项后关闭
- 点击外部区域关闭
- 按 Esc 关闭

### 3.4 修改或移除选择

- **移除**：点击 chip 上的 × → 归属栏回到"空 / 仅本会话"状态
- **更换**：点击 chip 重新打开下拉，选另一家公司

### 3.5 结果反馈（inline 提示）

- **归属确认成功**：inline 提示（例如："Added to [Company Name]'s memory."）
- **未归属（session-only）**：明确 inline 提示用户（例如："These files belong to session-only, not saved to memory." 或 "Available for this session only – not saved to memory."）

## 四、UX 设计考量

- 归属确认提示应作为**上传流程的自然一部分**出现，紧接在上传 chip 达到 Ready 状态之后，**inline 出现在聊天流中**，**不使用弹窗或阻塞式遮罩**。
- 提示要**简洁、以操作为导向**：清晰显示推断的公司名 + 单一"确认"操作 + 选择其他公司的入口。避免长篇解释文案。
- Portfolio Admin 选择其他公司时，用**简单的 inline 下拉或搜索选择器**即可，不需要单独页面或全屏模态。
- 归属结果的反馈必须 inline 清晰传达（见 3.5）。
- **文案要用 Portfolio Admin 能理解的自然语言**引用记忆目的地：使用如 "Portfolio Memory" 或 "Company Memory"，**避免使用 "Layer 1b" 这类技术术语**。

## 五、验收标准（Acceptance Criteria）

1. 一份或多份文件上传后，AI 尝试根据会话上下文推断归属公司，并在任何记忆处理开始**之前**，在 composer 上方 inline 显示公司归属确认条。
2. 归属条清晰展示所选/推断公司，并指明文件将被存储的位置。
3. 若 Portfolio Admin 确认 AI 推断的公司 → 文件被处理，摘要写入该公司的 Layer 1b 记忆文件（后端由配套 Story 处理）。
4. 若 Portfolio Admin 选择了与推断**不同**的公司 → 文件处理写入手动所选公司。
5. 若 AI 无法自信判断 → 公司槽位留空；Admin 点击后打开可搜索的公司下拉列表并手动选择。
6. 若未选择任何公司（槽位空 或 已选公司被移除）→ 文件**不写入任何** Layer 1b 记忆文件，仅作为当前会话中的文件存在。
7. **公司选择器视觉状态** —— 三种状态（空 / AI 推断 / 用户选择）表现如 3.2 描述。
8. **下拉行为** —— 满足 3.3 全部要求（打开方式、搜索、选中态、空结果、滚动、三种关闭条件）。
9. **修改或移除选择** —— 满足 3.4 描述。
10. 未归属的文件必须以 inline 方式**明确告知**用户"仅本会话，不保存至记忆"。
11. 一批上传只归属一家公司；已选归属时新增文件自动加入同一归属，不重置；只有在全部文件清空并开启新一次上传后，才启动新的独立归属流程。
12. 归属条**不阻塞聊天**，Portfolio Admin 在归属未定/已定状态下均可继续使用聊天。
13. Layer 1b 上传的文件**在任何情况下都不会**流入 GS 知识库（Layer 2）。
