# 需求文档：Company Memory File Layer 1a 后端 — 聊天提取：价值主张与 ROI 故事

**来源任务**：Company Memory File Layer 1a Backend - Chat Extraction: Value Proposition & ROI Story
**Asana 链接**：https://app.asana.com/1/1170332106480422/project/1202050347057533/task/1215298512189419
**适用模块**：AI Chatbot Layer 1a 后端 — 公司端聊天中**价值主张**与 **ROI 故事**的实时增量提取
**类型**：后端与数据架构需求（**无用户可见 UI**）

---

## 一、背景与范围

本需求覆盖公司端聊天对话中**价值主张（Value Proposition）**与 **ROI 故事**的**实时增量提取**到 Layer 1a 记忆文件。

### 为什么这件事重要
- **价值主张**是 AI 能理解一家公司的**最具战略意义**的事物之一——它定义：
  - **客户为什么付费购买产品**；
  - **产品解决了什么问题**；
  - **产品交付了什么成果**；
- 若缺乏价值主张上下文，AI 只能用**通用语言**讨论公司的财务表现；
- 有了价值主张上下文，AI 可以用**该公司业务专属的语言**来呈现洞察、基准、战略建议，使回复**显著更相关、更可行动**。

### 范围细则
- **价值主张** 包括：
  - 产品做什么；
  - 面向谁；
  - 解决什么核心问题；
  - 与替代方案如何差异化。
- **ROI 故事**进一步捕获：
  - 产品交付给客户的**具体、可量化的成果**；
  - 示例：时间节省、成本降低、收入增加、错误率降低，或创始人在解释"客户为何买"时提到的任何其他**可量化影响**；
  - **量化的 ROI 陈述**尤其有价值——它们为 AI 在帮助创始人在销售对话、投资人路演或战略规划讨论中**阐明价值**时提供**具体参照点**。

### 与 ICP 需求的清晰边界
- 本需求是**所有**价值主张、ROI、关键收益（key benefits）、差异化（differentiation）内容的**唯一归属**；
- **包括**当这些内容是在某个**具体 ICP 或客户细分**的语境中被描述时——例如创始人说："for our enterprise ICP, the key value is we reduce onboarding time by 60%"：
  - 这里的**细分语境（enterprise ICP）影响提取**（用作上下文标注）；
  - 但**提取出的条目**归属于**本需求**的记忆类别，**不归属** ICP 需求；
- 设计意图：
  - ICP 需求捕获 **客户是谁**；
  - 本需求捕获 **交付给客户的价值是什么**；
  - 两者**共同**构成完整的 go-to-market 画像；
  - 但**独立存储**以保持记忆结构**可查询且无冗余**。

### 提取模式
- 实时（real-time）、增量（incremental）；
- 在**每次消息交换**发生时即评估；
- **异步运行**，**不阻塞** AI 回复的交付。

## 二、功能描述

### 2.1 提取触发

- 提取为**实时增量**——在每次消息交换发生时即评估；
- 提取**异步运行**，**不阻塞**或延迟 AI 回复的交付。

### 2.2 价值主张（Value Proposition）提取

- **正确识别并提取**对话中浮现的价值主张陈述，包括：
  - 产品解决什么问题；
  - 产品与替代方案如何差异化；
  - 客户为什么选择它。
- **核心价值主张陈述**作为 Layer 1a 记忆条目存储，附 **source type（chat extraction）**与**时间戳**。
- **多 ICP / 多细分场景**：
  - 当公司端用户对**不同客户细分或不同 ICP** 描述了**不同的**价值主张时，**每个细分专属的价值主张**被分别提取与存储，**附带其关联的客户细分上下文**。
- **唯一归属**：本需求是所有**价值主张、关键收益、差异化**内容的**唯一**归属。
- **排除**：通用且无具体内容的营销语言（例如 "we make things easier"）**不提取**，**除非**伴随有足以使其有意义的**具体上下文**。

### 2.3 ROI 故事（ROI Story）提取

- **正确识别并提取**对话中提到的**可量化客户成果**，包括：
  - 成本节省（cost savings）；
  - 时间节省（time savings）；
  - 收入增长（revenue increases）；
  - 错误率降低（error reductions）；
  - 客户达成的其他具体结果。
- **量化 ROI 陈述**存储时需带：
  - **量化数字**；
  - **足以使其有意义的上下文**；
  - 示例："customers typically save 40% on processing costs"，存储时同时带上 **客户类型** 与 **何种流程** 的上下文。
- **未量化但具有方向性的 ROI 陈述**——若描述的是**一致的模式**——也被提取；
  - 示例："our customers see significant reduction in manual work within the first month"。
- **排除**：**一次性的、高度具体的客户结果故事**——若**不太可能**代表可重复的模式——**不**作为 ROI 条目提取。

### 2.4 冲突与更新处理

- 当新信息**更新**或**取代**先前的价值主张或 ROI 条目时，**先前条目被更新**以反映当前理解；
- 任意价值主张或 ROI 条目的**最新版本始终被视为权威版本**；
- **防止重复提取**已存于记忆文件中的信息。

### 2.5 性能与错误处理

- 失败的提取尝试**记录日志**，**不向用户暴露**任何错误；
- 即使单次提取失败，**Chatbot 继续正常运作**。

## 三、范围边界与跨需求约束

| 内容 | 归属 |
|---|---|
| 产品做什么 / 面向谁 / 解决什么核心问题 / 差异化 | **本需求**（价值主张） |
| 客户的可量化成果（节省成本/时间、增收、降错） | **本需求**（ROI 故事） |
| 未量化但描述一致模式的方向性 ROI | **本需求**（ROI 故事） |
| 在特定 ICP / 细分语境下表达的价值主张 / ROI | **本需求**（带客户细分上下文存储） |
| 关键收益（key benefits）、差异化（differentiation） | **本需求**（唯一归属） |
| 客户**是谁**（ICP 本体描述） | ICP 提取需求（不在本需求） |
| 通用且无具体内容的营销语言 | **不提取** |
| 一次性且不可重复的客户成果故事 | **不提取** |
