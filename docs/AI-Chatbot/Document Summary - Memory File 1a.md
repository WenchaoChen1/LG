# 需求文档：文档摘要 —— 记忆文件 1a（Document Summary - Memory File 1a）

> Asana Task GID: 1215976758492505
> Task Name: Document Summary - Memory File 1a

---

## 一、背景与业务描述

本需求覆盖公司侧（company-side）用户上传的所有文档（**不区分文件类型**）的**记忆摘要自动生成**逻辑。它是一个**共享的摘要层**，与各文件类型处理故事（PDF；Word & Plain Text）中的 RAG 索引流程**并行运行**。

其定位为：

- 与 RAG 索引平行的、跨文件类型统一的摘要生成机制；
- 生成结果作为长期上下文，随时间持续留存，即便用户在未来会话中未明确引用原文档，AI 亦可利用该摘要进行定位与理解。

---

## 二、业务逻辑闭环

当任意受支持类型的文档**成功完成 RAG 索引**后：

1. **摘要生成**
   - 系统调用 AI 读取该文档的完整内容；
   - 生成一份统一的 **1,000 字（1,000-word）摘要**，聚焦于文档中与公司相关的关键学习点；
   - 摘要以 **Layer 1a 记忆条目**形式保存，与 RAG 索引并存。

2. **版本约束**
   - 本版本**不含**公司特定内容过滤逻辑；
   - 所有上传文档均适用同一套 1,000 字默认摘要格式，与公司上下文无关；
   - 后续版本可考虑进一步优化摘要方法，例如引入公司相关性过滤逻辑。

3. **与 RAG 的关系（检索机制）**
   - 摘要**不是主要检索机制**，主要检索机制是 RAG；
   - 摘要作为**辅助上下文**，帮助 AI 在对话中定位到相关文档；
   - 针对已上传文档的查询，一律由 RAG 索引直接回答，摘要仅提供额外的方向指引；
   - 该机制确保：不会因摘要覆盖有限而使文档内容"静默不可访问"。

4. **数据隔离**
   - 所有生成的摘要严格限定在**原始上传公司的 Layer 1a 记忆文件**内；
   - 任何情况下均不得流入 Layer 1b 或 GS Knowledge Base（Layer 2）。

---

## 三、验收标准（Acceptance Criteria）

### 3.1 摘要生成

- 对于每一份成功完成 RAG 索引的上传文档（**跨所有受支持文件类型**），系统须自动生成一份**1,000 字**的公司相关关键学习点摘要。
- 所有上传文档均适用**同一套统一的 1,000 字默认摘要格式**；本版本**不引入公司特定内容过滤逻辑**。

### 3.2 存储与元数据

- 生成的摘要须保存为 **Layer 1a 记忆条目**，并附带以下元数据：
  - 来源类型（source type）：文档摘要（document summary）；
  - 原始文档名称（original document name）；
  - 文件类型（file type）；
  - 上传时间戳（upload timestamp）。

### 3.3 并行处理

- 摘要生成须与 RAG 索引**并行执行**，**不得**阻塞或延迟 RAG 索引流程。

### 3.4 无相关内容时的处理

- **仅当**文档完全不包含任何与公司相关的内容时，才不生成记忆摘要；
- 该情况下，文档仍可通过 RAG 检索访问，但**不会出现在 Memory Settings 面板中**；
- **摘要缺失不属于错误状态**，无需向用户发出任何通知。

### 3.5 摘要与 RAG 检索的关系

- 摘要**不对 RAG 检索进行门控或过滤**；
- 检索**一律**直接经由 RAG 索引完成。

### 3.6 数据隔离

- 所有生成的摘要严格限定在原始上传公司的 Layer 1a 文件内；
- 任何情况下均不得流入 Layer 1b 或 GS Knowledge Base（Layer 2）。

### 3.7 错误处理

- 摘要生成失败须记录日志以便排查，但**不得向终端用户暴露任何错误**；
- 摘要生成失败时，聊天机器人须保持正常运行 —— 摘要失败**不得**阻塞聊天体验或 RAG 检索。
