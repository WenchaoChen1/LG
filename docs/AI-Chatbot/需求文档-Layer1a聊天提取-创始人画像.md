# 需求文档：Company Memory File Layer 1a 后端 — 聊天信息提取：创始人画像

**来源任务**：[Asana LG-1396](https://app.asana.com/1/1170332106480422/project/1202050347057533/task/1214953638826108)
**UI 需求**：无（纯后端 / 数据架构 Story）

---

## 一、背景与业务目标

本需求覆盖从公司侧（Company-side）聊天对话中，**实时、增量式**地提取创始人（Founder）的心理特征与领导力画像信号。理解创始人的思考、沟通与决策方式，使 AI 能够以最适合该特定用户的方式组织回复——不仅准确，而且对接收者真正有用。

- 回避冲突、倾向延迟困难对话的创始人，与直接、数据驱动的创始人，需要不同的表达框架。
- 视觉型思考者与依赖详细书面框架者，需要不同的沟通方式。

创始人画像是**渐进、低干预**地构建的：通过创始人写作方式、提问内容、对挑战的回应、所用语言中自然存在的信号累积形成。多次对话之后，形成有意义的画像。该画像存储在 **Layer 1a 记忆文件**中，对 Company Admin 用户开放可见。用户可在 Memory Settings 面板查看并纠正画像，以改善聊天体验。

**关键说明**：
- Layer 1a 中的创始人画像代表 **AI 基于对话信号的观察性刻画**。在 Memory Settings 面板呈现时，必须以"观察到的倾向"措辞，而非标签式定义（例：写"倾向于通过把决策说出来来思考问题"，而非"外向型决策者"）。
- 底层模型采用 **DISC 框架**（Dominance、Influence、Steadiness、Conscientiousness），DISC 类型仅在系统内部用于结构化信号收集和驱动 AI 响应风格调整；面向创始人展示时，统一使用平实语言，**不出现 DISC 字母标签**。
- Portfolio Manager（GS 内部视角）对创始人的看法存储在独立的 **Layer 1b**，可能与 Layer 1a 不同，由另一个 Story 处理，不在本需求范围内。

## 二、功能需求

### 1. 提取触发机制（Extraction Trigger）
- 提取为**实时、增量式**：在每次消息交互时评估。
- **异步执行**，不阻塞 AI 回复的下发。

### 2. 创始人画像信号提取（Signal Extraction）
- 系统在对话出现规律时，正确识别并提取关于创始人的以下信号：
  - 领导风格
  - 沟通偏好
  - 决策倾向
- 每条合格信号根据消息中的**具体行为指标**映射到四个 DISC 维度之一：
  - **D（Dominance，支配）**：直奔结论、跳过上下文
  - **I（Influence，影响）**：富有热情、大局观式语言
  - **S（Steadiness，稳健）**：关注团队影响、偏好共识
  - **C（Conscientiousness，严谨）**：要求来源数据、方法论或精确性
- 每条信号作为**一条独立的证据条目（evidence entry）**存储，并带有对应的 DISC 标签。
- **仅记录有明确行为证据支持的观察**，不做主观推断。
- 每条证据条目用**不超过一句话**描述一种具体行为或表达。
- 画像观察必须以"观察到的倾向"措辞存储（带恰当的对冲语言），不可使用定性标签。
  - 例：写"在讨论财务表现时似乎偏好以数据驱动的方式表达"，而非"数据驱动型"。
- **单条消息信号不足以**生成画像条目，必须**跨多次对话出现规律**后才能生成创始人画像观察。

### 3. 类型分配（Type Assignment）

**滚动窗口**：基于**最近 20 条**证据条目（若不足 20 条则使用全部）计算画像类型，每新增一条证据即重新计算。

**Primary 类型（disc_primary）**：
- 窗口内出现次数最高的 DISC 类型。
- 最小阈值：≥ 5 条证据。

**Secondary 类型（disc_secondary）**：
- 出现次数第二高的 DISC 类型。
- 最小阈值：≥ 3 条证据。
- **必须在 DISC 圆环上与 Primary 相邻**。
- **允许的配对**：D-I、I-S、S-C、C-D。
- **排除的配对（对角线）**：D-S、I-C（行为取向冲突）。
- 若无任何类型达到次要阈值，`disc_secondary = null`，仅按 Primary 规则执行。

**Tie-breaking（同分处理）**：
- 若两种类型在 ≥5 条上并列：
  - 当前 `disc_primary` 保持不变，直到下一条证据打破平局。
  - 若当前尚未确立 Primary（仍为 unknown），则继续保持 unknown — **永远不会同时赋予两个 Primary 类型**。
- `disc_secondary` 同理。

**Fallback（兜底）**：
- 若没有类型达到最小阈值，`disc_primary = unknown`。
- 当 `disc_primary = unknown` 时，AI 使用**默认中性响应风格**，仅基于已收集的原始证据进行轻度风格化调整。

### 4. AI 响应规则（按单 DISC 类型）

**D（Dominance）**
- 首句直接给出结论，无前置铺垫。
- 答复保持简短。
- 使用主动语态、陈述句（"建议做 X"，而非"你或许可以考虑 X"）。
- 不加情感性安抚。
- 风险与问题直接陈述，不过度缓冲。

**I（Influence）**
- 先建立融洽气氛或肯定再进入正题。
- 偏好用例子和故事，而非数字列表。
- 语气轻盈，适度使用积极语言。
- 偏好"许多成功公司也在这样做……"式的措辞，而非直接引用硬数据。
- 负面信息表述为"值得关注的机会"。

**S（Steadiness）**
- 在引入任何变化或建议前，完整铺垫原因和影响。
- 给出**具体的下一步**以减少模糊性。
- 语气稳定，避免紧迫或突兀的措辞。
- 强调连续性（"这与你已在推进的方向一致……"）。
- 任何负面信息都搭配**过渡路径**一并呈现。

**C（Conscientiousness）**
- 回复需逻辑严谨，明示来源或推理依据。
- 避免模糊措辞（不用"通常""一般来说"，而用"在 X 条件下"）。
- **主动陈述假设和局限性**。
- 提供结构化分析（要点、步骤）。
- 不省略细节，宁可详尽也不留模糊。

### 5. 复合类型处理（Composite Type）

当 Secondary 类型合格时，AI 融合两套规则。**仅相邻组合出现**（D/I、D/C、I/S、S/C 及其反向），对角线组合（D/S、I/C）已被排除——其行为规则方向相反、无法有效融合。

| 组合 | 融合策略 |
|---|---|
| **D/I** | 先给结论，配以充满活力的表达 |
| **D/C** | 保持简洁，语气积极，强调影响与成果 |
| **I/S** | 先共情和肯定，突出对团队的正面影响 |
| **S/C** | 充分铺垫上下文 + 完整数据 + 清晰具体的下一步 |
| **I/D** | 保留富有活力、先建立融洽的语气，但仍保持果断并落到清晰结论 |
| **C/D** | 保留严谨和来源引用，但快速切入要点并先抛结论 |
| **S/I** | 保留稳健、令人安心的节奏，加入温度、鼓励和积极表达 |
| **C/S** | 保持结构化与精确，但节奏温和，强调稳定优于紧迫 |

### 6. 画像可访问性（Profile Accessibility）
- 创始人画像条目存储于 **Layer 1a**，对 **Company Admin 用户**在 **Memory Settings 只读面板**可见。
- 当 `disc_primary` 首次确立或后续发生变更时，生成并存储一份**人类可读的展示摘要（display summary）**：
  - 将主/次类型与支撑证据综合为平实的解释性语言。
  - 描述创始人的沟通风格和行为倾向。
  - 以"观察到的倾向"措辞，而非定性评估。
  - **摘要中不出现 DISC 字母标签**（D/I/S/C），类型仅在系统内部用于驱动措辞和 AI 响应风格。
- 该摘要即为 Company Admin 用户在 Memory 面板看到的内容。
- Portfolio Manager 的 GS 内部视角存储于独立的 **Layer 1b**，与 Layer 1a 的创始人画像不同。

### 7. 冲突与更新处理（Conflict and Update Handling）
- 当对话信号随时间表明先前的画像观察不准确或已发生变化时，**更新该条目**以反映最新刻画。
- **最新的画像观察始终作为权威版本**。

### 8. 性能与错误处理（Performance and Error Handling）
- 提取失败**写入日志**，不向用户暴露任何错误。
- 即使某次提取事件失败，**Chatbot 仍正常工作**。
