# AI Chatbot - Chat History（Company Portal）需求文档

## 一、需求背景

AI 聊天机器人须为公司端用户保存并展示历史会话记录。聊天历史使用户可以返回到之前的会话，回顾过往回答，并在无需重复上下文的情况下继续先前的问题线。

聊天历史与「记忆文件（memory file）」是相互独立、彼此区分的功能：
- 聊天历史：过往会话的完整、可读日志。
- 记忆文件：AI 从会话中提炼出的、用于改善后续回复的浓缩情报。

每个用户的聊天历史仅限于其本人的会话。Company Admin 也不能查看同公司内其他用户的聊天历史。无论角色为何，聊天历史都完全归属于产生该会话的个人用户。

MVP 阶段，聊天历史支持完整的会话管理动作：浏览、搜索、继续、置顶、重命名、删除，让公司端用户从第一天起就有一个熟悉且功能完整的历史使用体验。

## 二、适用范围

- 目标端：Company Portal（公司门户）。
- 用户角色：Company User、Company Admin。
- 平台：桌面端与移动端，均需完整可用（移动端响应式）。

## 三、功能需求

### 1. 入口与面板行为

- 聊天历史对 Company User 与 Company Admin 角色开放。
- 聊天历史面板通过聊天界面左侧栏的「历史」图标打开，以左侧滑出面板形式展示；同一控件可切换打开/关闭状态，也可通过 X 图标关闭。
- 「New Chat（新建会话）」按钮在任何时候都保持清晰可见，包括历史面板打开时。

### 2. 会话展示与组织

- 面板中的会话按最近时间分组：Today、Yesterday、Last Week、Older。
- 每个会话展示一个自动生成的标题，来源于用户在该会话中的第一条消息内容。标题在第一条消息发送时生成。
- 超过面板宽度的会话名称以省略号（…）截断显示，单行，不换行。
- 尚无任何消息的新会话，在第一条消息发送前显示默认标签「Untitled」。
- 当前正在打开的会话，在面板中以更深的灰色背景高亮显示；任意时刻只有一个会话处于激活态。
- 当用户没有任何历史会话时，面板显示空状态（例如「No chats found」）。

### 3. 搜索

- 面板内提供搜索栏。
- 支持按「会话名称」与「消息内容」搜索历史会话。

### 4. 继续过往会话

- 用户可在历史面板中点击任一历史会话，打开并回顾完整会话内容。
- 用户可通过选择某个历史会话并发送新消息来继续该会话；AI 在继续时保留先前会话的上下文。
- 返回到历史会话时，先前的消息展示在聊天线程中、位于新输入栏之前，让用户在继续之前获得完整上下文。

### 5. 会话行内操作（Hover）

- 鼠标悬停在某条会话行上时，出现三个操作图标：Pin（置顶）、Rename（重命名）、Delete（删除）。

#### 5.1 Pin（置顶）

- 点击 Pin 会将该会话置顶到聊天历史面板的最上方，进入一个专属的「Pinned」分组，该分组位于所有按最近时间分组的上方。
- Pinned 分组内多个置顶会话按最近置顶时间排序，最近置顶的在最上方。
- 一旦置顶，Pin 图标变为 Unpin 图标；点击 Unpin 将该会话从 Pinned 分组移除，并根据其最近活动时间回到相应的最近时间分组。
- 已置顶的会话，当其为当前打开的会话时，仍显示激活态高亮。
- 置顶/取消置顶操作不改变会话的内容和「最近更新时间」。

#### 5.2 Rename（重命名）

- 点击 Rename 将会话标题变为行内可编辑文本字段，预填当前名称并选中文本。
- 用户通过点击对勾图标（✓）或按下 Enter 键确认；按下 Esc 或点击其他位置则取消并恢复到原名称。
- 空名称不被允许：字段为空时 Save/✓ 按钮为禁用状态；即便确认时字段为空，重命名将被拒绝并保留原名称。
- 确认后，该行立即显示新名称。

#### 5.3 Delete（删除）

- 点击 Delete 弹出确认对话框，删除操作需二次确认。
- 对话框文案：
  - 标题：「Delete chat?」
  - 正文：「This will permanently delete this conversation and its messages. This action cannot be undone.」
  - 操作按钮：Cancel / Delete。
- 确认后，该会话从面板中永久删除。若被删除的会话是当前打开的会话，则界面回到「新建/空会话」状态。

### 6. 范围与隐私

- 聊天历史严格按登录用户个人范围隔离——用户无法查看任何其他用户的聊天历史，无论角色。
- 功能需为移动端响应式，桌面端与移动端均需完整可用。
