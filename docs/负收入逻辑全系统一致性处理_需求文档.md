**来源任务**：Asana - Handle Negative Revenue Logic Consistently Across the System
**任务链接**：https://app.asana.com/1/1170332106480422/project/1215285322971475/task/1214121140726212
**Sprint**：LG Sprint 111 (06.01.26 - 06.14.26)

## 一、业务背景与目标

Looking Glass 系统需要建立一套全系统统一、一致的负收入（Negative Revenue）处理规则。当前已发现多个场景中负收入会产生错误或误导性的计算结果，主要包括：

- **ARR 增长率（ARR Growth Rate）** 计算
- **基于收入的预测（Revenue-Base Forecasts）**
- **作为同行筛选基础的 ARR（ARR as Peer Filter Base）**

本需求需建立一整套覆盖整个系统的负收入处理规则，主要解决两类问题：

1. **个体公司指标计算层面**：负的前期 ARR 会导致 ARR 增长率公式产生误导性结果，需要特殊处理。
2. **基准（Benchmark）与同行计算层面**：基于负收入的基础值得到的数据点会扭曲分位数分布及同行比较，影响所有公司（不仅是负收入公司本身）。

除 ARR 增长率外，本需求还应审计系统中所有当前使用或可能引入负收入值的其他区域（包括基于收入的预测、作为 peer filter 基础的 ARR），并对每一处应用一致的处理规则。

## 二、功能描述与验收标准

### 1. ARR 增长率公式 —— 单公司视图

对所有公司一视同仁，按 ARR_t-1 的正负分三种情况：

| ARR_t-1 取值 | 计算公式 | 备注 |
|---|---|---|
| ARR_t-1 > 0 | ARR Growth Rate = (ARR_t − ARR_t-1) / ARR_t-1 | 公式不变 |
| ARR_t-1 = 0 或 null | ARR Growth Rate = 0 | 现有规则保持不变 |
| ARR_t-1 < 0 | ARR Growth Rate = (ARR_t − ARR_t-1) / \|ARR_t-1\| | 分母取绝对值 |

**示例**：

- 公司从 −100K 变为 +50K → ARR Growth Rate = +150%（回升正确显示为正向）
- 公司从 −100K 变为 −150K → ARR Growth Rate = −50%（继续下滑正确显示为负向）

### 2. Benchmark-ARR Growth Rate 同行对比的剔除规则

-  计算ARR Growth Rate 这个指标的benchmark时，在现有同行匹配规则基础上新增：**ARR_t-1 < 0** 的公司（期次数据点），从同行池中**完全排除**。

  - **现有同行匹配规则**

  ​    同行基于以下六个维度定义（必须同时满足）：

  1. **公司类型相同**（Company Settings中的Type）
  2. **公司阶段相同**（Company Settings中的Stage）
  3. **会计方法相同**（现金制 vs. 权责发生制）- **必填项**
  4. **ARR 规模相同（查看哪个月用哪个月的ARR,Actual找历史实际值，Committed forecast/System generated forecast数据分别用Committed forecast/System generated forecast ARR）**： " [$1, $250K) → 包含 $1，不包含 $250K" " [$250K, $1M) → 包含 $250K，不包含 $1M" " [$1M, $5M) → 包含 $1M，不包含 $5M" " [$5M, $20M] → 包含 $5M，包含 $20M" " ($20M, +∞) → $20M 及以上"
  5. **数据质量符合以下规则**
     - Actual数据时，从closed month开始往前数24个日历月内，连续六个月非负gross revenue，为有效数据公司，若有效同行 < 3 家，回退到全平台基准，显示 Peer Fallback 提示；
     - Committed forecast/System generated forecast数据时，从最后一个有预测数据的月份开始往前数24个日历月内，连续六个月非负gross revenue，为有效数据公司，若有效同行 < 3 家，回退到全平台基准，显示 Peer Fallback 提示。

  6. **排除条件** 
     - 以下状态的公司将被排除在同行计算之外：
     - Exited，
       Shut Down，
       Inactive

- 动态判定：剔除是按期间判定的，不是永久踢出某公司。某期间该同行 t-1 为负则本次剔除，其它期间不为负则照常纳入。

- 即使因匹配不到同行而回退到"全平台 active 公司"作为同行，同样执行此剔除规则。

- 此排除规则同时适用于：
  - LG 内部生成的基准（internal LG-derived benchmarks）
  - 任何 portfolio 级别的基准计算（portfolio-level benchmark calculations）
  
- 该排除 **不影响该公司自身 ARR 增长率的展示**，仅影响该数据点是否进入同行分布。

**示例**：

- 目标公司 A 算 2025-10 的 Actuals Internal Peer的ARR Growth Rate百分位，按现有规则匹配到同行 B、C、D、E。其中 B 在 2025-09（t-1）的 ARR < 0，则本次将 B 剔除。

### 3. 基于收入的预测（Revenue-Base Forecasts）

- 预测计算所使用的 **收入基础（revenue-base）必须排除负的 Gross Revenue**。
- 操作流程：
  1. 取last closed month的 Gross Revenue。
  2. 若该值为负，则从该月起 **向前回溯最多 24 个日历月**。
  3. 在回溯窗口内找到第一个 **非负（≥ 0）** 的 Gross Revenue 值，作为预测的有效收入基础。

### 4. ARR 作为同行筛选基础（ARR as Peer Filter Base）

同行筛选ARR 计算必须排除任何 Gross Revenue < 0 的公司-期次数据，**包括目标公司（target company)本身**。该排除在 Actuals（实际数据）与 Forecast（预测数据）下 **均为强制**。

- **Peer Groups 场景**：排除负收入异常值，确保 peer 分布不被扭曲。
- **Target Company 场景**：若 Target Company 的计算期内某月为负收入，该月必须被排除在用于确定 peer group scale 的 ARR 计算之外。
- **展示影响范围**：该排除 **不影响公司在常规视图中的 ARR 展示**，仅影响用于查找 peer group 的 ARR 计算值。
- **适用范围**：适用于 Benchmarking 和 System Generated Forecast Generation。

**示例**：

- 公司 A 配置为用历史三个月 gross revenue 计算 ARR。计算 2026-01 的 ARR 用于同行框定时，2025-11、2025-12、2026-01 的 gross revenue 分别为 10000、-1000、2000，其中 -1000 不计入，只用两个月：(10000 + 2000) / 2 × 12。

### 5. 系统全面审计（System-Wide Audit）

- 识别系统中所有当前处理或可能涉及负收入的其他区域。
- 对每一处确认其现有处理逻辑是否与本需求所建立的规则一致；如不一致，则按本需求规则进行更新对齐。
