# 需求文档：导入时自动计算 OPEX 总额以避免校验报错

**来源任务**：Auto-Calculate OPEX Total on Import to Prevent Validation Error
**Asana 链接**：https://app.asana.com/1/1170332106480422/project/1215698870864641/task/1215349591481274
**适用页面**：Looking Glass — Financial Entry（财务录入）页、Committed Forecast（承诺预测）页

---

## 一、背景与问题

### 1.1 现有校验规则
Financial Entry 与 Committed Forecast 页面均强制执行以下校验：
> OPEX 总额 ≥ 六个手动录入子项之和

六个手动录入子项为：
1. S&M Expenses（销售与市场费用）
2. S&M Payroll（销售与市场薪酬）
3. R&D Expenses（研发费用）
4. R&D Payroll（研发薪酬）
5. G&A Expenses（管理费用）
6. G&A Payroll（管理薪酬）

第七项 **Miscellaneous Operating Expenses（杂项运营费用）** 为计算字段，公式为：
> Miscellaneous = OPEX − 六个子项之和

该校验规则原本针对手动录入流程设计，在手动录入场景下运行正常。

### 1.2 问题场景（OCR 手动上传带来的边界情况）
当用户通过 OCR 手动上传功能导入财务文件时：
- 导入通道会将六个子项写入数据库；
- 但**不写入 OPEX 总额**，也**不写入 Miscellaneous**（这两项不包含在导入数据中）。

结果：导入提交后，OPEX 字段值为 0 或保留旧值，可能小于新导入的六个子项之和。当用户随后打开 Financial Entry 或 Committed Forecast 页进入编辑模式时，校验规则被触发并报错，导致用户**无法编辑数据**。

---

## 二、解决方案概述

在导入写入过程中，**由系统自动计算并写入正确的 OPEX 总额**，与子项数据在同一次写操作中提交到数据库。

关键约束：
- **仅在导入写入时进行一次性赋值**，不引入持久化的自动计算规则；
- 导入后，OPEX 仍为**手动录入字段**，用户可在页面正常编辑；
- Miscellaneous Operating Expenses 仍为**计算字段**，行为不变；
- 现有 OPEX 校验规则在手动编辑流程中**继续生效**，不做任何修改；
- Financial Entry 与 Committed Forecast 页面的 UI、校验逻辑、编辑行为**均无变更**。

---

## 三、功能描述

### 3.1 触发条件
- 导入包含六个 OPEX 子项中**至少一个**时，触发 OPEX 自动计算；
- 导入**未涉及任何**六个子项时，不执行 OPEX 重新计算，不修改 OPEX 字段。

### 3.2 计算公式（写入时）
> **OPEX = 写入后六个子项的生效值之和 + 该月已有的 Miscellaneous Operating Expenses 值**

### 3.3 写入时机
计算出的 OPEX 总额**与子项值在同一次写入操作中提交**到数据库，**不是后续的单独更新**。

---

## 四、数据来源与"生效值"的判定规则

按月独立判定。每个子项写入后的"生效值"按以下四类场景确定：

| 场景 | 子项生效值的取值 |
|---|---|
| **新月份（无历史数据）** | 使用导入值；未包含在导入中的子项视为 0 |
| **已有月份，无冲突** | 使用导入值；未包含在本次导入的子项，**保留数据库已有值** |
| **已有月份，冲突且用户选择覆盖** | 使用覆盖值（即导入值） |
| **已有月份，冲突且用户选择保留原值** | 保留数据库已有值 |

### 4.1 Miscellaneous 值的获取
- 写入前系统**预先读取该月数据库中已有的 Miscellaneous Operating Expenses 值**；
- 若该月无历史数据，Miscellaneous 在计算中视为 0。

### 4.2 多月导入
- 每个月份**独立**计算 OPEX，使用该月自身的生效子项值与已有 Miscellaneous 值；
- 未包含在导入中的月份**不受影响**。

---

## 五、操作流程（后端写入流程）

1. 解析导入数据，识别本次导入涉及的月份及六个 OPEX 子项。
2. 判断本次导入是否包含至少一个 OPEX 子项：
   - 否 → 不执行 OPEX 重新计算，按原流程写入，结束。
   - 是 → 进入步骤 3。
3. 对每个涉及月份执行：
   1. 预读取该月已有的 Miscellaneous Operating Expenses 值（无历史数据时取 0）。
   2. 依据冲突解决结果，确定该月六个子项各自的"写入后生效值"（参见第四节判定规则）。
   3. 计算：`OPEX = 六个生效值之和 + 已有 Miscellaneous 值`。
4. 在同一次写入操作中，将六个子项的导入/覆盖值与计算出的 OPEX 总额一起提交至数据库。
5. 写入完成后，数据库中 OPEX 总额与"六个子项之和 + Miscellaneous"保持一致。
