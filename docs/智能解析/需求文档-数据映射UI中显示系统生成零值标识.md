# 需求文档：数据映射 UI 中显示系统生成零值标识

**来源任务**：Display System-Generated Zero Indicator for Missing Monthly Values in Data Mapping UI
**Asana 链接**：https://app.asana.com/1/1170332106480422/project/1215698870864641/task/1215349591481277
**适用页面**：Data Mapping（数据映射）审查视图
**Figma 设计稿**：https://www.figma.com/design/QBhTPAljVPx673QWVrvfGw/2026---Portfolio-Portal?node-id=13471-5840

---

## 一、背景与问题

在对真实财务文档的测试中，Data Mapping UI 中发现一个边界场景：
- 财务报表中的部分**源财务科目**在文档日期范围内并非每个月都有数据；
- 按原需求，只要源财务科目某个月缺失数据，就会被**完全排除在 AI 映射之外**，并被放入 **Unmapped（未映射）** 区域。

但现实中，投资组合公司的财务报表里，财务科目在某些月份**合法地**没有活动是常见的。例如：
- 某个工资财务科目因为时点原因某个月为零；
- 某个费用财务科目只在特定季度有数值。

将这些财务科目完全排除在映射之外，会导致：
- 不必要的数据丢失；
- 用户被迫手动处理本可由系统自动处理的财务科目。

### 引申的透明度问题
若系统**静默地**将缺失月份填零，会引入信任问题：
- 创始人和财务团队需要确信映射视图中每个数值都真实反映源文件；
- 用户无法分辨"零"是来自文件还是系统生成时，可能误接受错误数据，或对导入流程失去信心。

因此，**系统生成的零值必须在视觉上区别于源文档中显式存在的零值**。

---

## 二、解决方案概述

1. **数据层**：在数据提取阶段（映射步骤之前），对源财务科目行中任一缺失的月度单元格**自动赋值为 0**，使 AI 能正常处理该财务科目的映射。
2. **展示层**：对系统生成的零值单元格添加**轻量化视觉标识**，并通过**悬停提示（Tooltip）**告知用户该零值是系统填充的默认值。
3. **交互层**：用户编辑该单元格后，标识与提示**永久移除**，新值视作用户手动输入。

---

## 三、功能描述

### 3.1 零值默认填充行为
- 当源财务科目行包含一个或多个空的月度单元格时，系统**自动为每个空单元格赋值为 0**，而不是排除该财务科目；
- 被填零的财务科目与数据完整的财务科目**一样进入 AI 映射流程**，不再仅因月度数据缺失被放入 Unmapped 区；
- 财务科目**只在满足其他不合格条件时**才会被放入 Unmapped 区，包括：
  - 缺少财务科目名称；
  - 无法识别的年-月（year-month）；
  - 无法识别的财务科目类型；
- 零值默认填充在**数据提取阶段（映射步骤之前）**执行；用户看到映射视图时，所有单元格都已有数值。

### 3.2 系统生成零值的视觉标识
- 含系统生成零值的单元格在视觉上**区别于源文档中显式为零的单元格**；
- 在系统生成零值的单元格上加一个**轻量化视觉标记**（例如：小图标、特殊样式的零、或浅色单元格背景），表明该值为系统填充；
- 用户**悬停标记**时显示 Tooltip，说明该财务科目该月在源文件中未找到数值，已默认为 0（示例文案："No value extracted. Defaulted to 0."）；
- 视觉标记与 Tooltip **仅出现在系统生成的零值单元格上**，源文档中显式为零的单元格**不显示**任何标识。

### 3.3 用户编辑行为
- 用户编辑一个系统生成零值的单元格并输入自己的值后：
  - 该单元格的系统生成零值标识与 Tooltip **永久移除**；
  - 同一行/财务科目中**其他**系统生成零值单元格**不受影响**，仍保留其标识；
- 新输入的值此后被视为**用户手动输入值**——即使用户输入的也是 0，标识也不会再出现；
- 一旦单元格被手动编辑，无论用户填入什么值，都不再被视为系统生成零值。

## 四、数据来源

| 数据项 | 来源 |
|---|---|
| 源财务科目与月度数值 | 用户上传的财务报表（数据提取阶段解析所得） |
| 空单元格的判定 | 提取阶段确定的源财务科目行中无值的月度单元格 |
| 填充值 | 系统默认 0 |
| 是否为系统生成零值的标记 | 提取阶段产生，随数据传递至 Data Mapping UI |
| 显式零值 | 源文档中本就为 0 的单元格（无系统生成标记） |

---

## 五、操作流程

### 5.1 数据提取与填零（系统）
1. 解析上传的财务文档，得到每个源财务科目及其月度数据；
2. 对每个源财务科目行，识别月度缺失单元格；
3. 将每个缺失单元格的值置为 0，并打上**"系统生成零值"标记**；
4. 源文档中显式为 0 的单元格保持原样，不打标记。

### 5.2 AI 映射（系统）
5. 所有源财务科目（包括被填零的财务科目）一并进入 AI 映射流程；
6. 仅在以下情况将财务科目放入 Unmapped：缺少财务科目名、无法识别的 year-month、无法识别的财务科目类型；
7. **不再**因仅缺少月度数据而将财务科目放入 Unmapped。

### 5.3 用户在 Data Mapping 视图查看与编辑
8. 映射视图中，系统生成零值的单元格显示数值 0，并附轻量化视觉标识；
9. 用户悬停标识，Tooltip 显示："No value extracted. Defaulted to 0."（或同义友好文案）；
10. 显式零值单元格不显示标识，无 Tooltip；
11. 用户编辑系统生成零值的单元格并提交新值：
    - 移除该单元格的标识与 Tooltip；
    - 新值视作用户手动输入（即便仍为 0），标识不再恢复；
12. 同一行中其他未被编辑的系统生成零值单元格不受影响。
