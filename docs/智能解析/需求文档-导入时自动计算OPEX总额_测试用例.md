# 测试用例：导入时自动计算 OPEX 总额以避免校验报错

- **需求来源**：https://github.com/WenchaoChen1/LG/blob/master/docs/智能解析/需求文档-导入时自动计算OPEX总额.md
- **Asana 任务**：Auto-Calculate OPEX Total on Import to Prevent Validation Error（task/1215349591481274）
- **适用页面**：Financial Entry（财务录入）页、Committed Forecast（承诺预测）页 — 后端导入写入流程 + 手动编辑保存路径
- **生成时间**：2026-06-18

> 约定缩写（六个手动录入子项）：S&M Exp（S&M Expenses）、S&M Pay（S&M Payroll）、R&D Exp、R&D Pay、G&A Exp、G&A Pay。
> 核心公式：**OPEX = 写入后六个子项生效值之和 + 该月已有 Miscellaneous（持久化列原样代入，null 按 0）**
> 关联公式（手动编辑保存路径）：**Miscellaneous = OPEX − 六个子项之和**（重算写回持久化列）

## 需求清单

| # | 需求类型 | 需求描述 |
|---|---------|---------|
| R1 | 业务规则 | 现有校验「OPEX 总额 ≥ 六个手动录入子项之和」在手动编辑流程中继续生效、不做修改；"≥" 含等于 |
| R2 | 功能需求 | 导入包含六个 OPEX 子项中至少一个时触发 OPEX 自动计算；未涉及任何子项时不重新计算、不修改 OPEX 字段 |
| R3 | 计算/业务规则 | 写入时 **OPEX = 六个子项生效值之和 + 该月已有 Miscellaneous 值** |
| R4 | 业务规则 | 子项"生效值"四类场景：①新月份→导入值，缺失子项=0；②已有月份无冲突→导入值，未导入子项保留 DB 值；③冲突且覆盖→覆盖值；④冲突且保留→DB 值 |
| R5 | 数据需求 | 已有 Miscellaneous 取数据库持久化列 `miscellaneous_operating_expenses` **原样代入**，不用实时派生值（OPEX−子项和）；列值 null 或新月份无历史时按 0 |
| R6 | 业务规则 | 导入时**只重算并写 OPEX 一个值**，不重算/不修正/不回写 misc 列（不做符号判断、不清零） |
| R7 | 边界条件 | 负费用场景：若 misc 列存值为 0，则 OPEX = 六个负子项之和（公式照常成立） |
| R8 | 业务规则 | 脏数据边界明确**不处理**：持久化列与页面派生显示在历史脏行上可能不一致，本功能只保证公式本身正确，不为脏行特殊处理，由数据订正单独解决 |
| R9 | 业务规则 | 计算出的 OPEX 与子项值在同一次写入操作中提交，非后续单独更新 |
| R10 | 业务规则 | 多月导入每月独立计算；未包含在导入中的月份不受影响 |
| R11 | 功能需求 | Actuals 路径走冲突校验/解决流程，按四类场景判定生效值 |
| R12 | 功能需求 | Committed Forecast 直存路径默认不调冲突校验、直接保存，但入库前同样执行 OPEX 自动计算；从该月数据库已有最新承诺预测行（base）取 misc 与未导入子项保留值；base 为空时取 0 |
| R13 | 业务规则 | Committed Forecast 范围限定：**只**从 base 取「6 个 OPEX 子项 + Miscellaneous」用于重算 OPEX，**不整行复制 base**；其余字段（Revenue/Cash/资产负债项/p05/p50/p95 分布字段等）维持"本次未导入即填 0"行为 |
| R14 | 业务规则 | 仅在导入写入时一次性赋值，不引入持久化自动计算规则；导入后 OPEX 仍为手动录入字段，可正常编辑，手动编辑不自动重算 OPEX |
| R15 | 业务规则 | Miscellaneous Operating Expenses 仍为计算字段，行为不变 |
| R16 | UI 需求 | Financial Entry 与 Committed Forecast 的 UI、校验逻辑、编辑行为均无变更 |
| R17 | 功能需求 | 写入后数据库 OPEX 与「六子项之和+Miscellaneous」一致；用户随后打开页面编辑不再触发校验报错（核心问题解决） |
| R18 | 功能需求 | 关联修复：手动编辑保存改某子项时，除非用户直接编辑了 Miscellaneous 字段，否则按 `Miscellaneous = OPEX − 六子项之和` 重算写回持久化列 |
| R19 | 业务规则 | 关联修复范围：仅手动编辑保存路径；用户直接编辑 misc 的行为保持不变；不改校验、不改 Cash 联动 |
| R20 | 业务规则 | 关联修复保证：任何保存后，持久化列 misc == 页面派生显示（OPEX−六子项），从源头消除列漂移，避免后续 OCR 导入时 misc 跳变 |

### 二、OPEX 计算公式与生效值判定（Actuals 路径）

| 编号 | 测试用例名称 | 前置条件 | 测试步骤 | 预期结果 |
|---|---|---|---|---|

| TC-010 | 公式含 Miscellaneous 完整验证 | 2026-06 已有 misc 持久化列=30；导入六子项之和=500 | 执行导入写入 | OPEX = 500 + 30 = **530**，体现 Miscellaneous 计入公式 |
