# 需求文档：数据映射 UI 中显示父级科目上下文

**来源任务**：Display Parent Account Context in Data Mapping UI
**Asana 链接**：https://app.asana.com/1/1170332106480422/project/1215698870864641/task/1215349591481275
**适用页面**：Data Mapping（数据映射）审查视图 — 源财务科目侧
**Figma 设计稿**：https://www.figma.com/design/QBhTPAljVPx673QWVrvfGw/2026---Portfolio-Portal?node-id=13471-5840

---

## 一、背景与问题

手动上传流程中的 Data Mapping 页面在映射视图左侧展示从上传文件中提取的源财务科目名称，供用户审查与确认每个行项目到 LG 财务类别的映射。

当前实现**仅展示叶子级别**的财务科目名称（即源文档科目层级中最低一级的名称）。这虽然技术上正确，但当一份财务文件中存在**多个同名但分属不同父级**的财务科目时，会造成混乱。

真实场景示例：
- **资产负债表**中可能出现两个 "Depreciation" 科目，一个在 "Computer Equipment" 之下，另一个在 "Furniture & Fixtures" 之下；
- "Original Cost" 也常见于多个资产父级类别下。

当这些科目仅以叶子名展示时，用户看到的是多行完全相同的名称（例如两行都叫 "Depreciation"），**无法在不回查原文档的情况下区分**，给映射审查带来不必要的摩擦——尤其是在审查详细资产负债表数据时。

---

## 二、解决方案概述

在 Data Mapping UI 的源财务科目侧新增一个 **父级科目上下文列**，与现有源财务科目名称列并列展示。

设计要点：
- **不修改财务科目名称本身**（避免父级名过长或跨多级时导致显示问题）；
- 父级科目上下文以**独立列**展示；
- 该列显示叶子级源财务科目的父级链；
- 顶级科目（无父级）该列**留空**；
- 仅作用于**源财务科目侧**，**不改动**底层映射逻辑、LG 类别分配或数据写入行为；
- 这是**纯展示层增强**，用于帮助用户在映射审查阶段准确识别与验证源财务科目。

---

## 三、功能描述

### 3.1 父级科目列展示
- 在 Data Mapping UI 的源财务科目区**新增一列**，紧邻现有的源财务科目名称列；
- 该列显示每个叶子级源财务科目的**父级科目名**，数据取自源文档的科目层级；
- 若源财务科目**无父级**（已经是顶级科目），该行此列**留空**；
- 若源财务科目存在**多级父层**，该列显示**完整父级链**，从最顶级父级到直接父级，每级以 `>` 分隔（例如：`Revenue > Operating Revenue > Service Revenue`）；
- 若完整链超出列宽，显示文本进行截断，**悬停时展示完整层级**；
- 该列需有明确标签（例如 `Extracted Parent`），让用户理解列的含义。

### 3.2 去重与消歧
- 当多行源财务科目共享同一叶子名称时，父级科目列需提供足够上下文加以区分（例如两行 "Depreciation" 分别显示 `Computer Equipment` 与 `Furniture & Fixtures`）；
- 该列对**所有**源财务科目行均填充，不论是否存在名称冲突；它始终作为**补充上下文**展示，而非仅在检测到重复时才出现。

### 3.3 范围与行为约束
- 本增强**仅作用于** Data Mapping 视图的源财务科目侧——LG 类别列与所有映射逻辑**不变**；
- 父级科目列为**纯展示**，**不影响**财务科目如何被映射、数据如何写入 LG，或导入管线的其他任何部分；
- 增强适用于**所有支持的、可能包含层级科目结构的文件类型**；
- 若源文档**无科目层级**（例如无父子结构的扁平 CSV），该列仍存在但**所有行留空**，不应导致错误或布局异常。

---

## 四、数据来源

| 数据项 | 来源 |
|---|---|
| 叶子级源财务科目名称 | 上传文件解析所得（现有数据） |
| 父级科目名 / 父级链 | 源文档的科目层级（提取阶段获得） |
| 无父级判定 | 提取的层级中该科目位于顶级 |
| 无层级文件的判定 | 解析阶段确定文件无父子结构（例如扁平 CSV） |

---

## 五、操作流程

### 5.1 数据准备（系统）
1. 解析上传文件，提取每个源财务科目及其在源文档中的层级关系；
2. 对每个叶子级源财务科目，构建从最顶级父级到直接父级的父级链；
3. 顶级科目的父级链置空；扁平文件的所有源财务科目父级链均置空。

### 5.2 视图渲染（系统）
4. 在 Data Mapping UI 源财务科目区渲染父级科目列，标题清晰（例如 `Extracted Parent`）；
5. 每行展示对应源财务科目的父级链：
   - 多级时用 `>` 分隔；
   - 顶级或无层级时单元格留空；
6. 当父级链超出列宽时，截断显示并在**悬停时显示完整层级**。

### 5.3 用户审查（用户）
7. 用户在映射审查中查看叶子级名称与其父级科目上下文，用以区分同名科目；
8. LG 类别列与映射逻辑**不变**——用户对映射的所有操作行为与之前一致；
9. 父级科目列**不可编辑**、**不影响**任何下游写入。
