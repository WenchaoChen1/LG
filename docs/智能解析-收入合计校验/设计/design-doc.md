## 1. 目标

映射审阅页（`/aIFinancialExtraction` 右侧 Mapped 区）在 **Gross Revenue 行的每个月份**旁显示一个校验徽标，
比对「映射后的 Gross Revenue 合计」与「源文件里的收入总计」：

- 一致 → 绿色 ✓：映射与源文件吻合，用户可直接通过；
- 不一致 → 黄色 ⚠：映射与源文件有偏差（漏映射、多映射、错行、错列、错月等），提醒用户审核；
- 无可比 → 不显示徽标。

本期只做 Gross Revenue；Net Income 等系统计算值不做。

## 2. 比对口径

### 2.1 源合计：只看源文件结构

- **源合计 = 源文件里「收入总计」行的值**，与映射结果完全无关（不能用"下面明细映射成了什么"去认合计行，否则错映射会让合计认不出来、反而掩盖偏差）。
- 源文件收入总计之外的项被映射进 Gross Revenue（包括按 LG 规则归入 Gross Revenue 的利息收入等营业外收入），**一律体现为不一致**，交给人工审核。
- 只认**合计行**（抽取阶段标为合计 / 小计的行），不认父科目自身的值，也不认普通明细。

### 2.2 哪些行算「收入总计」：标签白名单精确匹配

合计行标签规整（去**开头**的科目编号如 `4000` / `4000 ·` / `1.2.3`、去标点、转小写、压空白；标签中间或末尾的数字如年份**保留**，`Total Revenue 2025` 不算）后，**整串等于**下列之一才算；且只认金额单位（CURRENCY）的格，百分比等其它单位的格不算：

| 白名单 |
|---|
| `total income` |
| `total revenue` |
| `total revenues` |
| `gross revenue` |
| `total gross revenue` |
| `total for income`（QuickBooks Online 新版导出写法） |
| `total for revenue`（同上） |

- 精确匹配，不是包含：`Total Other Income`、`Total for Other Income`、`Total Other Revenue`、`Net Revenue` 都不算；`total for …` 只收上表两项，不泛化成"total for X 等同 total X"（实测 FreightTrain 的 QBO 导出用 `Total for Income`）。
- 不在白名单 → 视为没有源合计（不显示徽标），宁可不提示也不乱提示。

### 2.3 一张表里有多个白名单合计

| 关系 | 取法 |
|---|---|
| 嵌套（一个包在另一个里） | 只取最外层，不相加 |
| 并列（互不包含，上面没有更大的总计） | 相加 |

- Excel 轨：程序知道每个合计覆盖哪些行，能判嵌套 / 并列。
- PDF / 图片轨：程序看不到结构，**信任提示词**——提示词要求每段收入只输出最外层合计，故同一张表、同一月份出现多个白名单合计时**按并列相加**。模型若违规把嵌套的内层合计也输出，结果是多报一个 ⚠（用户复核即可），不会掩盖错误。
- **已知取舍（D14）**：同一层级先后出现两个白名单合计（如 `Gross Revenue` 小计 → `Less: Returns` → `Total Revenue` 同缩进），或 Excel 轨模型给合计与明细同深的扁平父链时，判不出嵌套，按并列相加 → 多报 ⚠（方向安全）。本地历史 135 个表格中 0 例出现同表多个白名单合计，本期维持现状。

### 2.4 汇总与比对

1. 每张表：按 §2.3 得到该表当月的源收入合计；
2. 同一文件：同一月份多张表相加；
3. 左侧选 **All Files**：跨文件相加；选单个文件：只算该文件；
4. 只算当前 tab（Actuals / Proforma）对应数据类型的表；
5. 与映射页 Gross Revenue 行当月合计（即该组父行的每月合计，随当前文件范围、tab、用户编辑实时变化）比较，**保留两位小数相等**为一致。

**同文件跨表重复月份（D13）**：同一文件里两张表含同一月份的相同明细（如单月 P&L + YTD P&L 都有 5 月），抽取阶段会把非权威表该月明细去重为一份；此时**该表该月的源合计一并剔除**，保证源合计与映射合计口径一致（否则源合计算两份、必报 ⚠ 且用户无法通过改映射消除）。

**部分表没写合计**：范围内只要有一张表有收入总计，当月就比对；没写合计的表不贡献源合计，但它映射到 Gross Revenue 的行照样计入映射合计，因此会报 ⚠（例：Board P&L 有 Total Income、QBD 数据页只有明细）。这是有意为之：源文件结构上不能自证一致的，交给人工复核。

### 2.5 不显示徽标的情况

- 当月没有任何源收入合计（源文件没写合计、白名单匹配不上、整张表没有日期——见 §4.3）；
- 有源合计但当前没有任何行映射到 Gross Revenue（Gross Revenue 组本就不渲染，维持现状）；
- 该月列存在多种币种（映射合计本就显示 "—"），或源合计与映射合计币种不同；
- 视觉轨输出被截断且未完全恢复的表、没有任何明细的表（含只有合计行的汇总页）：不存合计（宁可不比，不拿残缺数据误报；截断后拆半重发且完全恢复的批次照常保留合计）。

**要报 ⚠ 的边界**：Gross Revenue 组有显示、但某月没有映射值（"—"），而源文件该月有收入合计 → 按映射值 0 比对、报 ⚠（tooltip `Mapped: $0.00`）。典型来源：用户改错月份、视觉轨漏抽某列明细。与 D6 区别：D6 是整组无映射行、组不渲染。

### 2.6 月份对齐

源合计按源文件原始月份；映射合计按用户编辑后的有效月份。用户改错月份时两边对不上会报 ⚠，属预期。

## 3. 交互

- 位置：Mapped 区 Gross Revenue 组的父行（指标汇总行）每个月份金额后面；子行不挂。
- 样式：沿用映射页逐月小图标的做法（同"默认为 0"图标的位置与 tooltip 样式）。
  - 一致：对勾，Figma 组件「Check Mark - Default」，外框 16×16px、线条 Green/700 `#009344`（用 antd `CheckOutlined` 实现，不另引 SVG）；
  - 不一致：实心三角警告，Figma 组件「Warning」，外框 16×16px、三角 14×12px、颜色 Accent Yellow/700 `#E3C200`（用 antd `WarningFilled` 实现；注意与本页行警告三角的 `#F59F0A` 不同，按设计稿）。
- 设计稿里一致状态的 tooltip 写成 `$81K … Please review your mapping.`，与需求 AC 不符，按 AC 实现；设计稿第三种 ⓘ「No source total…」按 D5 不做。
- tooltip（金额格式与单元格一致，含币种符号）：
  - 不一致：`Source file: $273,357.26` / `Mapped: $136,678.63` / `Please review your mapping.`
  - 一致：`Source file: $136,678.63` / `Mapped: $136,678.63 ✓`
- 只读回放（devSupport 任务管理查看历史任务）同样显示。
- 不做"N of 12 months need review"汇总（需求列为后续可选）。

## 4. 抽取侧（Python）

### 4.1 Excel 坐标轨：合计行全部保留

- 提示词**不改**。现状已能准确识别合计行（模型标记 + 程序算术兜底），合计值由程序按单元格坐标读取，只是被丢弃。
- 改为：合计 / 小计行不产生映射数据，但连同标签、行号、每月数值一起保留进**独立的合计列表**（全部合计，不只收入；所覆盖的行范围只在程序内用于判嵌套，不落库）；隐藏的分析行（Projected / Variance 等）、比率行不进列表；取值、单位、符号翻转、币种与同列明细同规则。
- 收入总计按 §2.2 白名单 + §2.3 嵌套规则在程序侧挑选。
- 保留全部合计是为后续扩展其他指标校验预留数据，本期只消费收入总计。

### 4.2 PDF / 图片视觉轨：只输出收入段总计

- 提示词（因输出契约新增字段，由 `data_values.vision.v3.md` 升为 **`v4`**，D15）在输出 JSON 增加顶层字段 `_totals`（值直接是数组，通常 0~1 项），只放**营业收入段最外层**的合计行（标签、行号 rn、每个期间列数值）；营业外段（Other Income / Other Income (Expense) / Non-Operating Income）的合计一律不放。原有明细输出、"跳过合计行"规则不变；自检的行数 / cell 数不计 `_totals`，但其每个 cell 的月份须与同列明细一致。
- 程序拆分明细时跳过 `_totals`；对 `_totals` 再按白名单过滤（模型多给的 `Total Other Income` 等会被挡掉）。
- 页面没有收入合计时不输出 `_totals`（或空数组）。
- 风险：合计值由模型读图，没有程序按坐标回读核对。

### 4.3 合计与明细同口径

合计的每月数值与同表明细使用同一套列 → 月份对应、数据类型（文件声明类型）、币种，并同样执行「Actuals 丢弃当月及以后」。不参与补零、补行、映射记忆覆盖、语义分组、训练数据。

**缺日期**：
- 合计格自带列头月份时直接用；某列缺日期（没写或图片污染读不出）时，合计按列号借同表明细**推断后的月份**（合计不单独记推断标记）。用户在映射页确认推断月份 → 正常比；用户改成别的月份 → 合计仍在推断月，按 D7 报 ⚠。已知局限：视觉轨跨页续表重排列号后，无月份的合计格按原列号借月可能借错（概率低，代码已注明）。
- 整张表一个日期都没有：明细由用户逐行选择起始月份；合计无月份，**本期不参与比对**（视为该表没有源合计）。不做"合计跟随用户选择的日期"。

### 4.4 示例

Excel 轨程序整理后的单表合计列表（片段）：

| row | label | total_category | 2026-01 | 2026-02 | 2026-03 |
|---|---|---|---|---|---|
| 9 | Total Income | `GROSS_REVENUE` | 138,000 | 143,520 | 133,860 |
| 15 | Gross Profit | `OTHER` | 107,000 | 111,280 | 103,790 |
| 42 | Total Other Income | `OTHER`（不在白名单） | 300 | 312 | 291 |

视觉轨输出新增字段（其余不变）：`"_totals": [{"label": "Total Income", "row": 4, "ut": "CURRENCY", "cur": "USD", "cells": [{"col": 1, "mon": "2026-01", "v": 138000}, …]}]`

## 5. 数据模型

新增源合计表 **`ai_financial_extraction_source_total`**（业务库，迁移 `business/V033`），**不进** `ai_financial_extraction_mapping_data`（否则前端汇总、提交、Java verify / complete、映射记忆、语义分组都会把合计当科目重复计数）。

| 字段 | 含义 |
|---|---|
| id | 主键 |
| file_id / table_id | 所属文件与逻辑表 |
| source_account_label | 合计行原始标签 |
| source_row_order | 行序（同表内定位、判嵌套） |
| total_category | 合计用途枚举：`GROSS_REVENUE`（按 §2.2–2.3 选中的收入总计）/ `OTHER`（其余合计，默认）；后续扩展其他指标校验时加枚举值（如 `COGS`），表结构不变 |
| column_month | 月份（YYYY-MM） |
| value | 数值（源币种原值） |
| currency_type / unit_type | 币种 / 单位 |
| data_type | ACTUALS / PROFORMA（文件声明类型） |
| deleted / created_* / updated_* | 审计与软删。文件删除 / 替换时不改本表：读接口按 `ai_file_registry` 的删除状态整文件过滤；只有文件解析失败、清理残留明细时一并软删本表行 |

## 6. 接口

`GET /api/ai/financial-extract/tasks/{taskId}/extract-data`（含 `/increment`）的每个文件项新增 `sourceTotals`：

```
sourceTotals: [
  { tableId, label, totalCategory, columnMonth, value, currency, dataType }
]
```

- 返回该文件全部合计；前端本期只用 `totalCategory = GROSS_REVENUE` 的项。
- 只读回放接口 `/api/ai/financial-extract/manage/tasks/{taskId}/extract-data` 同样带 `sourceTotals`（D8 需要）。
- 旧任务（上线前抽取）无此字段或为空 → 不显示徽标。
- Java 不改：映射数据由 Python 直接给前端，提交链路不涉及合计。

## 7. 前端

- 接口类型增加 `sourceTotals`；文件数据合并（首次拉取 / 增量拉取 / 只读回放共用）时透传该字段。
- 按当前文件范围（单文件 / All Files）、当前 tab 的数据类型，把收入总计按月相加。
- Gross Revenue 父行每月：有源合计且币种单一 → 比对并显示徽标；否则不显示。
- tooltip 文案加入常量。

## 8. 测试与验收

- 单测：
  - Python：Excel 合计保留与白名单 / 嵌套挑选、视觉轨 `_totals` 解析与过滤（含同表多合计）、Actuals 截止对合计生效、落库与接口字段；
  - 前端：单文件 vs All Files、同文件多表相加、tab 过滤、用户改映射 / 改 Unmapped / 改月份后状态翻转、混币不显示、无源合计不显示。
- 实测（真实模型，挑代表文件）：
  - Excel：LG-1480 测试文件（Total Income + Total Other Income，期望利息收入导致 ⚠）、MXTR P&L（嵌套合计）、一份 Net Revenue 版式（期望不显示徽标）；
  - PDF：两份（含一份收入段有小计的）。
- 上线：
  - **V033 迁移必须在 Python 发版前执行（硬前置）**：读接口每次都会查新表，没建表时**所有任务**（含旧任务）的 extract-data、增量、只读回放都会报 500，映射页整体不可用。
  - Python 与前端谁先上都行——前端先上时 `sourceTotals` 缺失、徽标不显示，Python 先上时前端忽略该字段，均无副作用。
  - 过渡期：上线前抽取的旧任务里再追加新文件，All Files 下新文件有合计、旧文件没有，按 D10 会报 ⚠，属预期。

## 9. 决策台账（2026-10-20）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 合计提取范围 | 分轨：Excel 轨全部合计保留；视觉轨本期只输出收入段总计；数据结构按"全部合计"设计 |
| D2 | 源合计口径 | 只看源文件结构；收入总计之外的项映射进 Gross Revenue（含营业外收入）一律报不一致 |

| D4 | 多个合计 | 表内嵌套取最外层、并列相加；同文件跨表相加；All Files 跨文件相加；视觉轨同表同月多个 → 信任提示词按并列相加（违规时多报 ⚠，不掩盖错误） |
| D5 | 无源合计 | 不显示徽标（按需求 AC，不采用设计稿的 ⓘ） |

| D7 | 用户改月份 | 各按各的月份比对 |
| D8 | 只读回放 | 显示徽标 |
| D9 | 存储 | 独立源合计表 `ai_financial_extraction_source_total`，不进映射数据表；合计用途用枚举 `total_category`（本期 `GROSS_REVENUE` / `OTHER`，便于后续加其他合计）；Java 不改 |
| D10 | 同文件部分表没写合计 | 照常比对：没合计的表不贡献源合计、其映射行仍计入映射合计 → 报 ⚠，交人工复核（不按表拆分比对） |
| D11 | 合计缺日期 | 某列缺日期：用同表明细推断月份，用户改月按 D7 报 ⚠；整张表无日期：本期不参与比对（本地 190 张表中 18 张属此类） |
