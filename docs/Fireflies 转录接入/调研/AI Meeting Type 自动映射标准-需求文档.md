# AI Meeting Type 自动映射标准

**概述**：LG系统拉取到FF会议原始内容之后，需要识别参会人和会议类型，以供下一步路由使用，该文档就是说明**识别参会人员的规则**和**会议分类的标准**。识别出参会人员后，根据参会人员身份去判断会议类型，进而是对下游的路由内容分类起关键作用。

## **一、参会人识别**

- GS domain → LG user/company Team domain → cheat sheet → HubSpot → calendar name match → LLM inference → Pending Assignment.

**明确禁止**使用会议标题作为识别依据。

**GS域名** ：@whalesongproduct.com, @goldensection.com, @gst.com

**LG平台使用人员识别**：
- Email域名匹配平台中管理端和公司端用户，若email域名匹配为管理端用户，则认为此人是GS人员；若Email域名与客户端某公司域名一致，则认为此人是该公司人员，识别为Founder
- 客户端公司只查Active、Thriving、Needs Intervention、Needs Guidance状态的公司

**LG平台外人员：**

识别优先级（命中即止）：

1. **专家/参与人cheat sheet** 匹配，以会议发生日该人员的信息为准，若该日此人员身份有重复，则使用最新一条匹配
2. **HubSpot 联系人** 记录匹配
3. 先用Email匹配，未命中则用姓名匹配
4. **LLM 从转录内容推断** 
5. 仍无法解析 → 进入 Pending Assignment 队列

特殊说明:
- **Founder为专家时的识别**：若某人被识别为创始人（LG用户/公司匹配获胜），因此该会议被归类为 GS→Founder。但他仍需单独与注册信息核对以进行补充，从而显示其专家标志，因此一次会议可产生多个衍生结果（即分类和专家证词）。
- **专家推测**：
  - **触发条件:** 外部参与者(尚未被标记为专家)在证词类别中提出实质性主张时,Goldie会判断该主张能否归入专家标签覆盖的领域。如果可以归类,就显示专家推断。
  - **多标签:** 同一个人可以被推断为多个专家标签。
  - **管理员审核:** 管理员逐条确认或拒绝每个推断标签。拒绝时,系统记录该人员的email和被拒绝绝的标签,之后每周Goldie不会再就同一标签询问同一个人。被拒绝的只是这一个标签,Goldie然可以推断这个人的其他标签。
  - **排除规则:** GS员工永远不会被标记为专家。
  - **类别:** 种子列表中已有的五个类别是固定集合:多重投资、买家行为、退出趋势、软件使用、商业采购行为。只有管理员可以添加新类别,新类别会自动纳入专家推断的范围。
  - 保留一个独立的自由文本"专业领域"字段用于上下文说明,但该字段不用于路由,仅作描述性用途。

**何为GS人员**：
- Email地址属于管理端用户的
- Cheat sheet中role标签为GS Staff的
- 回退：若既不属于管理端用户，也未登记在册，则看域名是否是@goldensection.com、@whalesongproduct.com、@gst.com

补充规则：
- Cheat Sheet中的GS staff是未使用LG平台的GS人员，Founder是未使用LG平台的Founder人员。判定人员时，这两个标签的人员应正确归类
- 通过参与人 **邮箱域名** 匹配公司在 LG 中的 Team 记录，实现公司关联。
- 识别结果（公司、外部人员、角色）传递给下游分类步骤。
- 管理端应支持追溯"这场会议为何关联到此公司"（如"通过邮箱域名 acme.com 匹配至 Acme Inc"）以便 Pending 审核。（原型已包含）



## 二、会议分类规则

- 每场会议以"起止时间"为边界，作为 **单一整体** 进行分类和路由。
- **MVP 不做子会议切分**（即使参会人中途变化）。
- 若混合成分会议成为显著问题（如创始人离场后 GS 内部继续开），列为 Post-MVP。管理员可通过手动改判类型作为兜底。

### 五类会议 AI 分类

由 AI根据已识别参会人的身份推断分类，并保留 **发言人级归属**（who-said-what）用于下游证词抽取。

| 类型                                      | 触发规则                                                     | 备注                                           |
| ----------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| **GS → Founder**                          | ≥1 位 GS 人员 + ≥1 位founder人员                             | 与 Board Call 无法从参会数据自动区分，默认归此 |
| **GS Internal**                           | ≥2 位 GS 人员且无外部人员                                    |                                                |
| **GS → LP**                               | 参与人邮箱命中注册表 中LP角色；未命中则用姓名回退匹配注册表  | 依赖注册表已收录                               |
| **GS → Partner**（合并 Strategic + Exit） | 参与人命中注册表中 Strategic 或 Exit Partner；未命中则用姓名回退匹配注册表 | 两者无需区分，统一为一类                       |
| 通过以上规则以及LLM inference也无法判定      | **不猜测**，直接进入 Pending Assignment 队列。               |                                                |
