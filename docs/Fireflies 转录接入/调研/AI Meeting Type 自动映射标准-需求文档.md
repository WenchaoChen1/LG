# AI Meeting Type 自动映射标准

**概述**：LG系统拉取到FF会议原始内容之后，需要识别参会人和会议类型，以供下一步路由使用，该文档就是说明**识别参会人员的规则**和**会议分类的标准**。识别出参会人员后，根据参会人员身份去判断会议类型，进而是对下游的路由内容分类起关键作用。

## **一、参会人识别**

**明确禁止**使用会议标题作为识别依据。

**LG平台使用人员识别**：
- Email地址匹配平台中管理端和公司端用户，若email匹配为管理端用户，则认为此人是GS人员；若匹配为客户端用户，则认为此人是Founder,再去看此人属于哪家公司
- 客户端公司只查Active、Thriving、Needs Intervention、Needs Guidance状态的公司

**LG平台外人员：**

识别优先级（命中即止）：

1. **专家/参与人cheat sheet** 匹配
2. **HubSpot 联系人** 记录匹配
3. 先用Email匹配，未命中则用姓名匹配
4. **LLM 从转录内容推断** 
5. 仍无法解析 → 进入 Pending Assignment 队列

**何为GS人员**：
- Email地址属于管理端用户的
- Cheat sheet中role标签为GS Staff的
- 回退：若既不属于管理端用户，也未登记在册，则看域名是否是@goldensection.com、@whalesongproduct.com、@gstdev.com

补充规则：
- Cheat Sheet中的GS staff是未使用LG平台的GS人员，Founder是未使用LG平台的Founder人员。判定人员时，这两个标签的人员应正确归类
- 通过参与人 **邮箱地址** 匹配公司在 LG 中的 Team 记录，实现公司关联。
- 一场会议可关联 **多个公司**（多家公司参与人同时出现时）。
- 识别结果（公司、外部人员、角色）传递给下游分类步骤。
- 管理端应支持追溯"这场会议为何关联到此公司"（如"通过邮箱域名 acme.com 匹配至 Acme Inc"）以便 Pending 审核。（原型已包含）



## 二、会议分类规则

- 每场会议以"起止时间"为边界，作为 **单一整体** 进行分类和路由。
- **MVP 不做子会议切分**（即使参会人中途变化）。
- 若混合成分会议成为显著问题（如创始人离场后 GS 内部继续开），列为 Post-MVP。管理员可通过手动改判类型作为兜底。

### 五类会议 AI 分类

由 AI根据已识别参会人的身份推断分类，并保留 **发言人级归属**（who-said-what）用于下游证词抽取。

| 类型                                      | 触发规则                                                     | 备注                                                         |
| ----------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **GS → Founder**                          | ≥1 位 GS 人员 + ≥1 位founder人员                               | 与 Board Call 无法从参会数据自动区分，默认归此               |
| **GS → Board Call with Founder**(例外)    | 手动（AI不用判断此类)                                        | 由 Portfolio Group Manager 手动改判；改判需低摩擦（单下拉切换） |
| **GS Internal**                           | ≥2 位 GS 人员且无外部人员                                    |                                                              |
| **GS → LP**                               | 参与人邮箱命中注册表 中LP角色；未命中则用姓名回退匹配注册表  | 依赖注册表已收录                                             |
| **GS → Partner**（合并 Strategic + Exit） | 参与人命中注册表中 Strategic 或 Exit Partner；未命中则用姓名回退匹配注册表 | 两者无需区分，统一为一类                                     |

- 无法可信判定 → **不猜测**，直接进入 Pending Assignment 队列。
