# 题库草稿保存功能

## 原始需求：

题库并非一成不变的，而是会随时调整题目顺序和题目内容的。但是介于使用者不想改一个题就即时发布新题库（一般会在下个季度时发布新题库，省的发布了新的就要重新做）。

## 需求解读：

需要一个草稿保存功能以方便随时改但是可以统一发布。

## 功能：

### 功能更新

在 ERL Configuration 页面的 Publish 按钮旁边，新增一个 Save as Draft 按钮。

### 功能逻辑

#### 按钮激活规则

- 当用户对任一维度的题目顺序或内容进行修改后，Save as Draft 按钮即被激活。

- 保存草稿后：
  - 当前页面展示的内容即为最新草稿，草稿按钮置灰；

  - Publish 按钮变为激活状态，用户可随时提交发布。

- 若存在草稿，页面需展示提示文案，格式如下：

▎ Draft saved 【Time】by 【Name】

示例：

▎ Draft saved 4 Nov 2026, 06:59 (UTC) by GSV Assessment Team

#### 开发注意事项

1. 历史版本管理

- 用户查看当前使用的版本题库时，需点击 View History 按钮。
- 开发时需将当前已发布的版本也一并纳入历史记录中。

2. 保存/发布的作用范围

- Save as Draft 和 Publish 按钮的操作范围是所有维度，并非针对单一维度。
- 用户在修改过程中可自由切换各维度的 tab 进行编辑。
- 全部修改完成后，点击：
  - Save as Draft → 将所有维度的改动一并保存为新草稿；
  - Publish → 将所有维度的改动一并发布为新版本。

## 已确认口径（2026-11-18）

设计稿：<https://lovable.dev/projects/c0fe1ad4-229b-4020-b2ed-1a3991662787?preview-path=%2Ferl-configuration>（设计稿里没有 Discard Change 按钮，Name 是写死的示例值，以下口径为准）。

1. **草稿只有一份**：每个组织一份，多个管理员共用。后保存的整份覆盖先保存的，不提示冲突。发布同理：一张打开较早的页面点 Publish，会把期间别人存的草稿、甚至别人已发布的新版本盖回去，已接受。
2. **改动先留在页面上**：新增、编辑、删除、调顺序、改 Era band 都只改页面，点 Save as Draft 或 Publish 才提交。没点保存就离开或刷新页面，未保存的改动直接丢弃，不弹确认。
3. **没存草稿也可以直接 Publish**：Publish 生效的是页面当前显示的题库，可能与草稿相同，也可能比草稿新。发布后草稿清空，提示文案消失。
4. **新增 Discard Change 按钮**：连草稿一起丢弃，页面回到已发布版本。只要存在草稿或页面有未保存改动，按钮即可点。
5. **提示文案里的 Name**：取保存草稿的操作人用户名。
6. **恢复停用的维度时，题一起带回**：在 Dimension Configuration 里恢复一个停用维度，若停用期间发布过新版本（新版本里没有这个维度），它停用前最后一次发布的题会自动放进草稿，发布后该维度连题一起恢复；点 Discard Change 则这批题一起丢掉。停用后没发布过新版本的，恢复后题本来就在。
7. **编辑页与历史页显示的内容**：问题编辑页面显示的是草稿，或基于草稿的未保存修改。View History 默认展示当前在用版本，历史页右上方的 Version 下拉默认选中的也是当前在用版本。

### 按钮状态

| 页面状态 | Save as Draft | Publish | Discard Change | 提示文案 |
|---|---|---|---|---|
| 无草稿、无未保存改动 | 置灰 | 置灰 | 置灰 | 不显示 |
| 无草稿、有未保存改动 | 可点 | 可点 | 可点 | 不显示 |
| 有草稿、无未保存改动 | 置灰 | 可点 | 可点 | 显示 |
| 有草稿、有未保存改动 | 可点 | 可点 | 可点 | 显示上一次保存的时间与保存人 |
