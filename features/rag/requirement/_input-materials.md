## 一、需求背景

LG（CIOaaS）平台目前已具备 AI 财务抽取能力，但**缺少通用的"RAG 管理"功能**：

- 用户无法把公司内部资料、政策文档、销售话术、产品手册等沉淀到一个可被 LLM 检索的库
- 未来的 Chatbot / Agent 没有"公司专属知识"可调用
- 文本知识只能反复在对话里粘贴

本次需求即新增一个完整的**RAG 管理**模块，覆盖：建库、上传/录入、向量化、检索、统计、管理。

## 二、产品定位

**核心使用场景**：为未来的 LangGraph Chatbot 提供 RAG（检索增强）能力。

**用户感受**：类似 Dify / Coze 的"RAG"模块——
- 我能为公司创建多个RAG（产品文档、销售资料、客户案例……）
- 我能上传文件或直接录入文本到某个RAG
- 我能看到每个文件被切成多少分块、被检索调用了多少次
- 我能输入一个 query，测试检索结果是否符合预期
- 未来 Chatbot 接入时可自动从指定RAG里召回相关内容

## 三、三轮头脑风暴决策摘要

### 第一轮（架构方向）

| 维度 | 决策 |
|---|---|
| 主要消费方 | **Chatbot RAG**（聚焦单一场景，元数据按 RAG 优先） |
| 与现有 `ai_files` 表关系 | **保持关联关系**：`task_id` 改为可空 + `ai_files` 加文件类型字段（FINANCIAL / RAG） |

| Java / Python 接入边界 | **Python 直供全部 REST**（Java 仅做认证转发） |

### 第二轮（业务范围）

| 维度 | 决策 |
|---|---|
| RAG归属粒度 | **多元化**：公司级多空间 + 用户个人空间都要支持（"很多可能性"） |
| 前端 MVP 范围 | **全部要**：空间 CRUD / 文件上传+进度 / 文本直传 / 分块预览 + 检索测试 / **Dify 风格统计页**（片段数、引用次数、token 消耗） |
| 异步触发机制 | **Python `BackgroundTasks`**；上传链路解耦：**前端从 Java 取 S3 预签名 → 直传 S3 → 完成后调 Python 触发向量化** |
| Embedding 模型管理 | **走 `source/llm/providers/` 抽象**（统一调度 + tracing + 计费记录） |

### 第三轮（补充）

| # | 补充需求 |
|---|---|
| 1 | **文件读取与拆分策略要可配置**：系统提供默认的读取/拆分规则；同时允许通过接口参数覆盖（chunk_size、chunk_overlap、分隔符等） |
| 2 | **要有完整的搜索接口能力**：不只是单一查询，需支持多空间联合、过滤条件、混合检索（关键词+向量）等 |

## 四、CIOaas-python 项目现状摘要（业务向）

- 已有 `ai_files` 表，绑定到"财务抽取任务"。本需求要**扩展其用途**让它能承载RAG文件
- 已有 `files`（Java 写）、`company`、`user` 表，本需求**复用**
- 已有 LLM 多供应商抽象（OpenAI / Anthropic / DeepSeek / OpenRouter），本需求**扩展**出 embedding 子家族
- 已有 SQS 异步消费链路（财务抽取用），本需求**不复用**，改走 `BackgroundTasks`
- `esapiens-python/esapiens/embedding_pipeline/` 已有完整文件加载 / 拆分 / 向量化 / ES 存储实现（10 种文件类型 + 文本直传），但该目录**不在主仓库 Git 范围内**，本需求需要把它**搬入** `CIOaas-python` 并本地化

## 五、用户角色与权限模型（待确认细节）

| 角色 | 期望能力 |
|---|---|
| 公司管理员 | 创建/编辑/删除公司级RAG空间；管理本公司所有空间下的文件；查看本公司所有空间统计 |
| 普通用户 | 创建/管理自己的个人空间；在自己可见的空间（本公司所有公司级空间 + 自己的个人空间）里上传/检索 |

## 六、功能清单（高层）

### F1. RAG空间管理
- 创建空间（指定 `owner_type=COMPANY|USER`、名称、描述、embedding 模型、拆分规则等配置）
- 编辑空间（基本信息、embedding 模型一旦有数据后能否改？待确认）
- 删除空间（含级联清理向量数据）
- 列出当前用户可见的空间

### F2. 文件入库
- **前置**：Java 出 S3 预签名 → 前端直传 S3 → 通知 Java 写 `files` 表
- 前端调 `POST /rag/files`：传 `file_id` + `space_id` +（可选）拆分参数覆盖
- Python 立即建任务，返回 `task_id`，BackgroundTasks 异步执行
- 任务进度查询：成功数、失败数、错误明细
- 支持的文件类型：CSV / PDF / DOC / DOCX / XLS / XLSX / PNG / JPG / JPEG / EPUB + 纯文本

### F3. 文本直传入库
- 前端提交 `POST /rag/texts`：标题 + 内容 + `space_id` +（可选）拆分参数
- 同样建任务、BackgroundTasks 执行向量化

### F4. 文件读取 + 拆分（可参数化）— **第三轮补充**
- 系统提供**默认的拆分规则**（chunk_size / overlap / 分隔符按文件类型差异化）
- 接口允许调用方传参覆盖默认规则（创建空间时设默认 + 单次入库时可临时覆盖）
- 拆分结果可被前端预览（GET `/rag/entries/{id}/chunks`）

### F5. 搜索（检索）— **第三轮补充**
- **基础检索**：`POST /rag/search`，传 query + top_k + space_ids 数组
- **混合检索**：支持向量召回 + 关键词召回融合（ES 后端原生支持，PG 后端走分段策略）
- **过滤条件**：文件类型、来源类型（FILE/TEXT）、上传时间区间、特定 entry_id 列表
- **返回内容**：命中的 chunk 内容 + 来源文件信息 + 命中相似度
- **副作用**：每次检索写 `rag_search_log` + 累加命中 chunk 的 `hit_count`（用于统计页）

### F6. Dify 风格统计页
- 单个空间维度：总分块数、总 token、被检索次数、最近热门 query
- 单个 entry（文件 / 文本）维度：自身被命中次数、最常被命中的 chunk 排行

### F7. 配置与维护
- 单文件大小上限（默认 50MB）
- 失败文件可重试
- 软删除窗口（默认 30 天）

## 七、待 `pm-questioner` 整理给用户澄清的疑点（候选）

> 以下是头脑风暴时识别出的"未决业务问题"，由 `pm-questioner` 进一步扩充后批量发给用户回答。

### 关于空间所有者
1. 公司管理员是否能管理 / 看到普通用户的个人空间？（默认否）
2. 用户离职后，他名下的个人空间如何处理？（删除 / 转交 / 归档？）
3. 一个用户能创建多少个人空间？（无上限 / 限额？）
4. 公司级空间能否被设置成"只读分发"（创建者维护，他人只读检索）？

### 关于文件入库
5. 是否允许重复入库同一文件到同一空间？（去重还是允许多版本？）
6. 单批可上传的文件数量上限？
7. 入库失败的文件是否扣占空间配额？（如有配额）
8. PDF / 图片是否需要走 OCR？还是只走文本提取？（esapiens 默认是文本提取，不走 OCR）

### 关于文件读取 + 拆分
9. 默认拆分规则按文件类型差异化吗？还是统一一个 chunk_size？
10. 拆分参数可覆盖范围：仅 chunk_size / overlap，还是包含分隔符、最小块大小、标题保留等高级项？
11. 拆分结果是否允许用户手动编辑（重新切分、合并）？（首期建议否）
12. 同一文件用不同拆分参数二次入库，是否覆盖还是并存？

### 关于检索
13. 默认 top_k 是多少？最大 top_k 上限？
14. 混合检索的关键词召回是否对中英文都做？（中文要不要分词器？）
15. 检索时是否支持时效衰减（新文件优先）？
16. 检索 API 是否要返回 chunk 上下文（前后相邻 chunk）？
17. 调用方身份：必须传 user_id 做权限过滤，还是允许 service account 全公司检索？

### 关于统计
18. 引用次数：所有命中都 +1，还是只 top-3 / 用户实际点击的才 +1？
19. 统计页要保留多久历史？（30 天 / 90 天 / 永久？）

### 关于配置与维护
20. 失败文件的"重试"是从头重做还是断点续传？
21. 软删除窗口内的空间能否恢复？
22. embedding 模型在空间创建后是否允许变更？变更后历史向量怎么处理？

### 关于成本控制
23. 是否对单空间设置 token / 文件数 / 存储量配额？
24. embedding 调用是否要走 LLM 调用追踪表（已存在 `llm_call_log` 类设计）？

## 八、不在本次范围（明确划界）

- ❌ **不**搭建 Chatbot UI（仅提供RAG + 检索 API，未来 Chatbot 单独立项）
- ❌ **不**做权限审计日志 UI（数据库层 `rag_search_log` 有记录，但不出审计页面）
- ❌ **不**做多语言翻译 / 跨语种检索
- ❌ **不**做知识图谱 / 实体抽取（纯向量 + 关键词）
- ❌ **不**做付费 / 配额收费（仅在后端字段预留，不出收费 UI）
