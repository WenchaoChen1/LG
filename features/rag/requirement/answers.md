## 二、用户明确决策（5 项）

| 编号 | 决策 | 含义 | 后续影响 |
|---|---|---|---|
| **A1=C** | 管理员可完整查看并操作员工的个人空间 | 管理员对公司内全部空间（含个人空间）有完整管理权限 | UI 上要明确告知员工"管理员可见"，避免隐私误解；权限矩阵需修订；空间列表查询要按"管理员=公司内全部"过滤 |
| **A2=C** | 管理员既能看统计聚合，也能看员工个人空间的详细统计 | 与 A1 一致延伸 | 统计页要区分"公司聚合视图"与"按用户钻取视图" |
| **B1=B** | 图片文件走 OCR，全部提取文字后入库 | PNG / JPG / JPEG 全部走 OCR | 需引入 OCR 服务（候选：现有 financial 模块的 AWS Textract / GPT-4o vision / 其它）；文件处理时间预期延长；§2.3 入库可见性指标可能要单独说明"图片类型可超 10 秒" |
| **F1=B** | 允许变更 embedding 模型；变更后历史数据全量重新向量化 | 用户切换模型时触发"全量重跑"任务 | 需设计模型迁移任务的 UI 反馈（类似批量入库进度条）；要警示用户重跑成本与时间 |
| **H1=B** | OCR 纳入本期范围 | 范围扩张确认 | §7"不在本次范围"删除 OCR 相关条目；§4.2.5 文件类型规则更新；测试用例增加 OCR 场景 |

## 四、自动头脑风暴补充决策（用户未问但需要明确）

> 以下是 pm-writer 在修正定稿过程中可能需要的进一步细化，按"自己头脑风暴 + 默认"原则预先决策：

| 项目 | 决策 | 理由 |
|---|---|---|
| OCR 服务选型 | 优先复用 `CIOaas-python/source/lg/pdf_processor.py` / `financial_extract` 链路中已用的 OCR 实现；若该实现不通用，则用 GPT-4o vision 走 `source/llm/providers/` 抽象 | 减少新依赖、统一调度链路 |
| Embedding 模型变更触发"全量重跑"的 UI 反馈 | 与常规入库任务同样的"进度条 + 失败计数"，并在空间页加一条横幅"模型迁移中" | 复用已有 UI 组件 |
| OCR 文件类型的入库可见性指标 | §2.3 增加注解"图片/扫描件类型 10 秒可见但不保证 10 秒内完成处理" | 显式与 G1=A 协调 |
| A1=C 下个人空间隐私告知方式 | 在创建个人空间表单和上传文件提示框都加一句"本公司管理员可查看本空间内容与统计" | 透明、避免纠纷 |
| OCR 调用失败时的回退 | OCR 失败的图片仅保留文件名与元数据可被检索，正文 chunk 数计为 0、entry.status=PARTIAL | 不让单图失败拖垮整批 |

## 五、本次答复对需求文档的修订指引（给 pm-writer）

请按以下修订点把答复回填到 `requirement-doc.md`：

1. **§2.3 衡量指标** — 入库可见性目标增加注解："纯文本/Office 类型 10 秒内可见；图片/扫描件类型由于走 OCR，10 秒内可见任务但不保证 10 秒内完成处理"
2. **§4.1.4 规则 3** — 改为"允许变更 embedding 模型；变更后系统自动触发全量重新向量化任务，期间空间状态显示'迁移中'，迁移过程中检索仍可正常使用旧向量"
3. **§4.2.5 规则 4（同名文件去重）** — 改为"上传同名文件时提示'已存在，是否覆盖'，确认覆盖则删除旧条目重建"
4. **§4.2.5 规则 5（图片处理）** — 改为"PNG/JPG/JPEG 通过 OCR 提取文字后入库；OCR 失败时仅保留文件名可检索，正文不入库"
5. **§4.2 增补** — 单次批量上传上限：10 个文件
6. **§4.3.4 文本字数** — 上限 100,000 字
7. **§4.4.2 可调拆分参数** — 明确"用户可调整：片段大小、片段重叠量（共 2 项）；分隔符等高级项由系统自动处理"
8. **§4.4.5 规则 2（重新切割）** — 改为"以新参数重新入库时，覆盖该文件原有的全部片段（被命中统计随之清零）"
9. **§4.5.2 检索参数** — top_k 默认 5、最大 20
10. **§4.5 增补** — 明确"本期不返回命中片段的上下文（前后相邻片段）"、"不做中文分词"、"不做时效衰减"
11. **§4.6.4 命中规则** — 改为"top_k 范围内所有命中片段都累加 1 次命中"
12. **§4.6.4 统计保留** — 热门 query 列表保留 30 天，命中次数累计值永久保留
13. **§4.7.2 重试** — 明确"从头重做：删除该文件的全部中间结果与已生成片段，重新执行入库流程"
14. **§4.7.3 软删除** — 明确"本期不出自助恢复 UI；删除确认弹框告知'30 天内可联系管理员恢复'"
15. **§5.1 权限矩阵** — 管理员对个人空间改为"完整查看 / 编辑 / 删除"；增补告知机制（创建/上传时透明告知用户"管理员可见"）
16. **§5.3 系统调用方** — 改为"必须携带用户身份；无 user_id 的调用一律拒绝"
17. **§6.1 容量** — 改为"本期不设单空间 / 单公司文件数量与存储容量上限；后端字段预留"
18. **§6.2 性能** — 三项指标作为验收硬性标准；§2.3 已对图片类型做注解
19. **§7 不在本次范围** — 删除"OCR"相关条目；保留"跨语种检索"和"片段手动编辑"
20. **§9 术语表** — 新增"OCR"、"全量重新向量化（模型迁移）"两个术语
